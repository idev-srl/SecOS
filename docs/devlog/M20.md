# M20 — Unified page cache + file-backed mmap

**State:** done. Self-test harness **96/96** (was 91/91; +5 M20 assertions).
Demo gated behind `M20_MMAP_DEMO`, off by default. Closes Phase G (VM completeness).

## Goal

A single cache of file pages that backs **both** file `read()` and **file-backed
`mmap`**, so the two are coherent (they share the same pages). This also lays the
groundwork for sharing read-only text across processes (the M14 per-process
pinned image is the obvious next consumer).

## What landed

### Page cache — `mm/pagecache.{c,h}` (new)
A small fixed cache (`PC_ENTRIES = 128`) of 4 KB pages keyed by
`(inode, page-aligned offset)`. `pagecache_get_phys(inode, off)` returns the
physical frame of the cached page, populating it from the VFS (`inode->ops->read`)
on a miss and zero-padding past EOF; FIFO eviction frees the frame. `pagecache_read`
copies a byte range out through the cache; `pagecache_invalidate` drops pages after
a write so the next read re-populates. Cache frames are **kernel-only** — see the
MAP_PRIVATE note below — so eviction is a plain `pmm_free_frame`.

### File-backed mmap (MAP_PRIVATE) — `mm/vma.{c,h}`, `kernel/syscall.c`
`vma_t` gains an alternative FILE backing: a `file_inode` + `file_voff` served
through the page cache (vs. M14's pinned-image `file_base`). `vma_add_file`
registers such a region; `vma_fault_in` materializes a page by **copying the file's
cached page into a fresh private frame** (MAP_PRIVATE: the process gets its own
writable copy; the cache page stays shared and kernel-only). `SYS_MMAP` gained a
5th arg `fd`: with `MAP_ANONYMOUS` it's the M18 anonymous path, otherwise it maps
the fd's inode from file offset 0. libc `mmap_file(addr, len, prot, flags, fd)`.

### read()/write() go through the cache — `kernel/syscall.c`
`ksys_read` now calls `pagecache_read`, so file `read()` and file-backed `mmap`
source bytes from the **same** cache pages (coherent). `ksys_write` calls
`pagecache_invalidate` for the written range (write-through to the VFS + drop stale
cache pages). libc gained `read`/`open`/`close` wrappers.

### Demo + harness — `kernel/kernel.c` (`M20_MMAP_DEMO`), `user/m20_mmap.c`
The kernel writes a known file (`/m20.txt` = `"M20-PAGE-CACHE-OK"`) into the VFS,
then runs the signed `m20_mmap`: it `open`s the file, `mmap_file`s it read-only,
checks the mapped bytes match, `read()`s the same file, and confirms `read()` and
`mmap` returned **identical bytes** (coherence). Five assertions.

## Things worth noting

- **Why MAP_PRIVATE keeps the cache kernel-only:** each fault copies the cache
  page into a private frame, so no process maps a cache frame directly. That makes
  eviction trivial (no shared mappings to invalidate) and write-to-mapping safe
  (it hits the private copy, never the file). A future `MAP_SHARED` (and shared
  read-only text) would map cache frames directly and need refcounting +
  writeback — deferred.
- **Coherence scope:** read+mmap share cache pages, and `write()` invalidates the
  cache, so a subsequent `read`/`mmap` sees the new bytes. A page already faulted
  into a process's private MAP_PRIVATE copy does **not** retroactively change — that
  is exactly POSIX MAP_PRIVATE semantics.
- **read() path change is the regression surface:** `ksys_read` routing through
  the cache means the full self-test (which exercises VFS reads, M9/M10) is the
  guard — re-run green.

## Deferred / next

- **MAP_SHARED + shared read-only text:** map cache frames directly (refcounted)
  so multiple processes share one copy of an executable's text; retire the M14
  per-process pinned image. The headline future win of the page cache.
- **Writeback / fsync / dirty tracking:** the cache is currently read-populate +
  invalidate-on-write (write-through to the VFS). A real dirty-page writeback path
  belongs with Phase H (storage maturity / journaling).
- Phase G (VM completeness) is now complete: demand paging (M14), dynamic memory
  (M18), COW fork (M19), page cache (M20). Next up: **pipes + TTY** (unblocked by
  fork) and Phase H (storage) / Phase I (APIC + SMP) per
  `docs/ROADMAP_TO_COMPLETE_OS.md`.
