# M11 — Driver Space for real (signature-rooted capability boundary)

**State:** done. Self-test harness **47/47** (was 38/38; +9 M11 assertions).
Demo gated behind `M11_DRIVER_DEMO`, off by default; normal boot reaches the shell.

## Goal

Turn the existing Driver Space *plumbing* (registry, bindings, caps, audit,
rate-limit — all in `kernel/driver_if.c` since M1) into a real **security
boundary rooted in the code signature**:

1. A process is a **driver** only if its signed `.note.secos` manifest says so.
2. A driver gets **capability-mediated** hardware access via `SYS_DRIVER`, and is
   refused anything outside the capabilities the manifest granted — with audit.
3. A plain user process has **no** driver rights at all.

Before M11 the privilege was granted by an interactive shell command (`drvreg`)
with no link to the signature, and `SYS_DRIVER` never checked *who* was calling.

## What landed

### Manifest v2 carries the driver claim (`mm/elf_manifest.*`)
- `elf_manifest_raw_t` gains four optional v2 fields: `proc_type`, `dev_id`,
  `dev_caps`, `reserved` (desc grows 24 → 40 bytes; `version` bumps to 2).
- The parser is **descsz-aware**: a v1 manifest (24-byte desc) still parses and
  defaults to `PROC_TYPE_USER` with no grant, so existing binaries (`hello`)
  are unaffected. Driver fields are read only when `version >= 2` **and**
  `descsz >= 40`.
- The signature digest is SHA-256 over the whole file (QSIG sig zeroed), so the
  QSEC manifest — including the driver claim — is **covered by the signature**.
  Tampering with `proc_type`/`dev_caps` invalidates the Ed25519 signature and the
  loader refuses the binary. The signature is the trust root for the claim.

### PCB + loader (`kernel/process.*`)
- PCB gains `proc_type` / `drv_dev_id` / `drv_caps` (default USER / -1 / 0).
- After signature-verify + manifest-parse, if the manifest declares
  `PROC_TYPE_DRIVER`, `process_create_from_elf` validates the device, intersects
  the requested caps with what the device actually supports (never grants more),
  and **auto-binds** the process via `driver_register_binding_caps`. A bogus
  claim (unknown device / no slot) degrades to USER — the process still runs but
  `SYS_DRIVER` will refuse it.
- `process_destroy` now calls `driver_remove_all_bindings(p)` **first**: the
  registry holds a `process_t*`, and a stale pointer surviving `kfree(p)` could
  later alias a reused process and hand it the dead driver's device. (Latent
  use-after-free / privilege-leak fixed.)

### Capability enforcement (`kernel/driver_if.*`)
- `driver_binding_t` carries the granted `caps` subset.
- `check_driver_permissions` now enforces, in order:
  1. **`proc_type == PROC_TYPE_DRIVER`** → else `DRV_ERR_NOTDRV` (-7). This is
     the boundary: a user process is refused before any device/binding check.
  2. binding present, opcode→cap, **granted caps** (per binding), device caps,
     range. Enforcing against the *granted* subset (not just device-supported)
     means a driver granted `READ|WRITE|GET_INFO` is refused `MAP_MEM` even on a
     device that supports it.
- Seed device 0 now advertises `MAP_MEM|UNMAP_MEM` so the *grant* boundary is
  distinguishable from the *device-support* boundary in the demo.
- `driver_audit_log` mirrors every audited event to debugcon (`[DRV-AUDIT] pid
  dev op res`), so the boundary is verifiable non-interactively. Denials are
  always audited; successes only with `DRV_FLAG_REQUIRE_AUDIT`.
- The manual/dev path (`drvreg` shell command) now also sets `proc_type=DRIVER`
  and grants the device's full caps, so the interactive `drvtest` still works.

### User-space driver (`user/`)
- `user/secos_driver.h`: user-side ABI mirroring the kernel `driver_call_t`
  layout exactly (so `SYS_DRIVER` copy_from/to_user round-trips); opcodes, caps,
  error codes. `libsecos` gains `secos_driver()` (SYS_DRIVER = 7).
- `user/drvprobe.c`: shared `drvprobe_run(tag)` exercising GET_INFO / WRITE_REG /
  READ_REG (granted) and MAP_MEM (not granted), one `write()` per line so the
  output stays contiguous against the per-syscall debugcon trace.
- Built into **two signed binaries** differing only by their manifest:
  - `driver_demo` (`user/note_driver.S`: `PROC_TYPE_DRIVER`, dev 0, caps `0x13`)
  - `userprobe` (`user/note.S`: `PROC_TYPE_USER`)
- `make user-progs` builds+signs both → `crypto/user_driver_elf.h`,
  `crypto/user_userprobe_elf.h` (committed; kernel build stays python-free).

### Demo + harness (`kernel/kernel.c`, `tools/selftest.sh`)
- Gate `M11_DRIVER_DEMO`: an idle task runs the signed driver, then the signed
  user probe, back-to-back, printing `[M11]` markers and `DONE`.
- 9 new assertions: driver bound from manifest (dev0 caps 0x13), runs as DRIVER,
  mediated reg read/write **round-trips** (`val=0xcafef00dd15ea5ed`), un-granted
  MAP_MEM refused (`ret=-1`), user probe runs as USER, user denied SYS_DRIVER
  (`ret=-7`), ≥8 audit records, `[M11] DONE`, no `[EXC]`.

## Gotcha uncovered: heap caps single allocations at one frame

The demo first loaded the driver ELF via the VFS (like M9/M10's `hello`). It was
**refused at the signature gate** — non-deterministically. Root cause:
`mm/heap.c` builds the heap one PMM frame at a time; each free block is at most
`PMM_FRAME_SIZE - header` (~4072 B). `kmalloc(size)` larger than that can only be
satisfied if physically-contiguous frames happened to coalesce into a big enough
free block — otherwise **`kmalloc` returns an undersized block without failing**.
ramfs copies file data with one `kmalloc(file_size)`; for a ~7.5 KB ELF that
overflowed the block, corrupting the stored bytes → digest mismatch → refused.
`hello` (6 KB) only worked by luck of the heap state.

Fix for M11: load the embedded **signed** ELF directly with
`process_create_from_elf` (still fully signature-verified) — no VFS/heap
roundtrip, deterministic. The real fix (a buddy / multi-frame allocator, and
`kmalloc` returning NULL instead of an undersized block) is an **M12** item; the
limitation is now documented rather than latent.

## Files

- `mm/elf_manifest.{h,c}` — v2 manifest fields + descsz-aware parse.
- `kernel/process.{h,c}` — `proc_type`/grant fields, auto-bind, binding cleanup.
- `kernel/driver_if.{h,c}` — granted-caps binding, proc_type+grant enforcement,
  debugcon audit, `driver_remove_all_bindings`, device-0 caps.
- `kernel/shell.c` — `drvreg` sets proc_type (manual/dev path).
- `user/secos_driver.h`, `user/libsecos.*`, `user/drvprobe.c`,
  `user/driver_demo.c`, `user/userprobe.c`, `user/note_driver.S`.
- `kernel/kernel.c` — `M11_DRIVER_DEMO` gate. `Makefile` — user-progs.
- `tools/selftest.sh` — +9 M11 assertions. `crypto/user_{driver,userprobe}_elf.h`.

## Not in M11 (future)

- `DRIVER_OP_MAP_MEM` real MMIO mapping into the driver address space (still a
  validating stub) — needs the device-memory VMM path (`docs/DRIVER_SPACE.md` §5).
- IRQ delivery to drivers (`DRIVER_OP_IRQ_SUBSCRIBE` + IPC queue), DMA sandbox,
  automatic restart of a crashed critical driver.
- Multi-frame heap allocator (M12) so large files/ELFs go through the VFS again.
