# M9 Devlog — Real userland + mandatory ELF signing

**Branch:** `milestone/M7`
**Tag:** `M9_STABLE`
**Status:** COMPLETE

---

## Summary

M9 turns SecOS from "a kernel that boots" into "an OS that runs real, **signed**
programs". Userland and code-signing were built together because the loader is
the verification point and the user toolchain is the signing point. The
signature is the **root of trust** for the `.note.secos` manifest claims — the
basis of the three-mode model (kernel / driver / user; `docs/DRIVER_SPACE.md`).

End-to-end, verified by `tools/selftest.sh` (14/14):
- A `hello.c` is compiled + linked with the SecOS crt0/libc into an ELF, **signed**
  by `tools/secos-sign` (Ed25519), embedded, written to the VFS as `/bin/hello`,
  **loaded back from the VFS**, its signature **verified by the kernel**, and run
  in ring-3 where it prints via `SYS_WRITE` and exits cleanly.
- A **tampered** copy is **refused** by the loader gate.

## Pieces

### Crypto (in-kernel, freestanding, no malloc)
- `crypto/sha256.{c,h}`, `crypto/sha512.{c,h}` (FIPS 180-4).
- `crypto/ed25519.{c,h}` — detached verify (RFC 8032; field arithmetic from
  TweetNaCl, public domain). The kernel only verifies; the private key never
  ships on-device.
- `crypto/crypto_selftest.c` — known-answer tests (SHA-256/512 vectors; Ed25519
  accept/reject; end-to-end ELF-signature accept + two tamper rejects). Run at
  boot; `[CRYPTO] --- all PASS ---`.

### Signing format & tools (`docs/SIGNING.md`)
- `.note.secos` carries a QSEC manifest and a QSIG `{version, key_id, sig[64]}`.
- **Digest** = SHA-256 over the whole ELF file with the 64 sig bytes zeroed
  (covers header, program headers, segments, manifest); Ed25519 signs the digest.
  One definition shared by host (`tools/secos_signlib.py`) and kernel
  (`mm/elf_sign.c`).
- `tools/secos-keygen` (emits the kernel pubkey header), `tools/secos-sign`
  (signs an ELF in place), `tools/elf2h.py` (embed an ELF as a C array). DEV key
  derives from a fixed seed for bootstrap; production swaps in a real key.

### Loader gate
- `mm/elf_sign.c::elf_signature_verify()` finds the QSIG note, recomputes the
  digest, `ed25519_verify` against the embedded trusted pubkey.
- `process_create_from_elf()` calls it and **refuses** any ELF without a valid
  signature, unless built with `-DDEV_ALLOW_UNSIGNED` (bootstrap; the M7/M8
  synthetic demos use this, since they build ELFs at runtime and can't be signed).
- `mm/elf.c`: skip zero-size PT_LOAD segments before the user-range check (a
  linker may emit an empty `.data` at vaddr 0).

### Userland toolchain
- `user/crt0.S` (`_start` → `main` → `SYS_EXIT`), `user/note.S` (the
  `.note.secos`), `user/libsecos.{c,h}` (syscall wrappers + a small POSIX-friendly
  surface: `write`, `_exit`, `getpid`, `sched_yield`, `strlen`, `puts`),
  `user/user.ld` (code at `USER_CODE_BASE`, data at `USER_DATA_BASE`,
  `-mcmodel=large` for the 4 GB+ layout), `user/hello.c`.
- `make user-progs` builds + signs `user/hello.elf` and regenerates
  `crypto/user_hello_elf.h` (committed; keeps the kernel build python-free).
- `kernel/syscall.c`: `SYS_WRITE` to fd 1/2 writes to the console (terminal +
  serial) and mirrors to debugcon so user output is captured headlessly.

## Notes / next

- The default build **enforces** signing (the gate is on but dormant at boot —
  nothing is auto-loaded). Unsigned ELFs (`elfload` of the embedded test driver)
  are now correctly refused.
- The libc is intentionally tiny; it grows a POSIX-friendly surface as
  open-source programs are ported (port-from-source + sign; not Linux binaries).
- `SYS_SPAWN`/`SYS_WAIT` and a shell `run <path>` are natural follow-ups; the
  loader/VFS/signature plumbing they need is now in place.
