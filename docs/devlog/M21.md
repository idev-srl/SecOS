# M21 — AHCI (SATA) storage driver

**State:** done. Self-test harness **102/102** (was 96/96; +6 M21 assertions).
Always-on (no gate). First driver for **real-hardware / VMware storage**.

## Goal

Make `/mnt` work on **VMware** and **physical PCs**, which expose **SATA (AHCI)**
controllers — not virtio-blk (a QEMU/KVM-only device). The existing FS stack
(FAT32/ext2/ext4) sits on the abstract `block_dev_t`, so this is purely a new
block driver: probe the AHCI HBA, IDENTIFY the SATA disk, read/write sectors, and
register it — the filesystems plug in unchanged.

## What landed

### PCI helpers — `drivers/pci.{c,h}`
- `pci_find_class(class, subclass, progif, …)` — find a device by class bytes
  (AHCI = `01/06/01`), since AHCI isn't a fixed vendor/device.
- `pci_enable_mem_and_busmaster()` — enable memory space + bus mastering (AHCI is
  MMIO, unlike virtio-blk's port I/O).
- `pci_bar_mem(d, idx)` — read a memory BAR base (AHCI's ABAR is **BAR5**).

### AHCI driver — `drivers/ahci.c` (new)
Probes the HBA, maps its registers (ABAR via the physmap, `vmm_extend_physmap` to
be safe), sets `GHC.AE`, and walks the implemented ports. Every **established
SATA** port (`PxSSTS` DET=3/IPM=1, `PxSIG`=`0x00000101`) is brought up:
- `port_rebase` points the port at a per-port command list + received-FIS buffer
  and starts it (`FRE`/`ST`).
- `ahci_identify` issues ATA `IDENTIFY` and reads the LBA48 (or LBA28) capacity.
- read/write use ATA `READ/WRITE DMA EXT` on command slot 0 with a single PRDT
  entry over a shared bounce buffer; completion is **polled** (`PxCI`/`PxTFD`,
  `PxIS.TFES` for errors). DMA structures are static aligned kernel buffers;
  physical addresses come from `kvirt_to_phys`.

Each disk is registered as `block_dev_t` **"sda", "sdb", …** (up to 4).

### Multiple disks + mount-tries-each — `kernel/kernel.c`
Crucial for VMware: there the **boot ESP and the data disk are both SATA**, so the
first port is usually the GPT/ESP boot disk, not the data disk. AHCI therefore
registers *all* SATA disks, and the boot mount logic tries
`vda, sda, sdb, sdc, sdd` and mounts the **first that holds a FAT32/extN volume** —
the ESP disk is skipped automatically (it's a GPT, not a raw FS). `ahci_init()` is
called at boot right after the virtio probe.

### Tooling + docs — `Makefile`, `docs/RUN_ON_HARDWARE.md`
`make data-vmdk` builds a pre-formatted FAT32 **data disk** (`data.vmdk`) to attach
in VMware as a SATA disk → `/mnt`. The hardware guide now documents the SATA data
disk (and the "use SATA, raw FS, no partition table" requirements).

## Verification (in QEMU, before VMware)

`q35` has a built-in AHCI controller, so the whole driver is testable locally:

- **ISO boot + 1 SATA data disk** → `sda` found, FAT32 mounts, read + write+readback OK.
- **UEFI boot from a SATA ESP + a SATA data disk** (the VMware shape): `sda` =
  ESP/GPT (skipped by mount), `sdb` = data → FAT32 mounts, read + write+readback OK.
- ext2 data disk also mounts read-write.
- `tools/selftest.sh` → **102/102** (new M21 block boots a `q35` AHCI disk and
  asserts `[AHCI]` ready + FAT32 mount + read + write+readback, no `[EXC]`).

This is the proof it works on VMware/SATA and physical SATA machines.

## Things worth noting

- **Bounce DMA**: every transfer goes through a static aligned buffer, so caller
  buffers need no contiguity/alignment — same trade-off as virtio-blk.
- **One command at a time**: the kernel is single-threaded and polls, so the
  command table + bounce buffer are shared across ports; only the command list +
  received-FIS are per-port (the HBA reads those continuously).
- **No IRQ**: completion is polled (`PxCI`), matching the rest of the storage path.

## Deferred / next

- **NVMe** (M22) — NVMe-only laptops + VMware's NVMe option. Same `block_dev_t`
  shape, admin/IO submission+completion queues instead of SATA ports.
- **USB** (keyboard + Mass Storage) — needed to *use* USB devices after boot
  (booting from USB is the firmware's job, no driver needed). Big: XHCI + USB core
  + HID + MSC/BOT + SCSI. Tracked for after NVMe.
- **Partition tables** (GPT/MBR) — would let `/mnt` come from a partition on the
  boot disk instead of a separate raw-FS disk.
- **ATAPI / optical (ISO9660)** — niche; not planned.
