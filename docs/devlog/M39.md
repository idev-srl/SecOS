# M39 — Secure boot, full kernel W^X, user ASLR, POSIX foundation, bash from source, ath9k_hw port

M39 is a bundle rather than one subsystem: it executed the four "NEXT candidates"
left after Phase L (M35–M37) and M38 — secure boot, the rest of W^X + ASLR, WiFi
association, and a shell compiled from source — then followed bash all the way to
"boot into bash", and started porting the upstream Linux ath9k_hw radio driver.
Each item landed as its own validated commit (both smoke paths PASS, selftest
182/182 at `8762198`/`e66a57f`, 0 `[EXC]`).

## Secure boot — UEFI loader verifies the kernel (`61f52c7`)

Trust now runs firmware → loader → kernel → signed programs (closes the gap left
in M37, where the kernel was only *measured*).

- **Kernel side**: `boot/kernel_note.S` adds a `.note.secos` QSEC manifest + QSIG
  signature note as its own `SHT_NOTE` section (`linker.ld`), so `ld` emits a
  `PT_NOTE` phdr. The Makefile signs `kernel.bin` in place after link
  (`tools/secos-sign --dev`, deterministic → reproducible builds stay
  byte-identical). `linker.ld` also discards orphan `.eh_frame` (an unprotected RWX
  gap inside the LOAD segment).
- **Loader side**: `uefi/secure_boot.c` `secure_boot_verify()` = SHA-256(file, 64
  sig bytes zeroed) + Ed25519 against `secos_trusted_pubkey` — the identical digest
  rule to `mm/elf_sign.c`. `crypto/{sha256,sha512,ed25519}.c` are compiled into the
  loader. `elf_load.c` verifies right after reading `kernel.elf`, before parsing;
  read buffer 1 MB → 16 MB. Enforced by default; `SECURE_BOOT=0` disables.
- **MB2/GRUB path ignores the note** — an unsigned kernel still boots via ISO/CI.
  Secure boot is therefore a property of the UEFI loader path only.

Validated in QEMU+OVMF: signed → `[SECURE BOOT] kernel signature OK` → shell; one
flipped byte → `signature INVALID - refusing to boot`, kernel never executes.

## Full high-half kernel W^X + boot-time auditor (`021d445`)

`vmm_protect_kernel_sections` had existed since M36 but was **never called**: the
high-half kernel image ran RWX (only the low identity map had been NX'd).

- Rewritten physmap-consistent (the old raw-physical PT walk faulted for
  page-table frames above 512 MB) with explicit 2 MB → 4 KB splitting that carries
  NX from the PDE. One sweep over the 2 MB-aligned image span: `.text` RX;
  `.data/.bss/stack` RW+NX; everything else (rodata, the signing note, padding, the
  tail of the last split huge page) R+NX.
- NX on every other 2 MB huge page of the high-half phys 0–512 MB window (a
  duplicate RAM view that was RWX).
- Called from `kernel_main_phase2` after `idt_init` and physmap init. Gate:
  `-DSECOS_NO_WX`. `vmm_audit_wx()` walks the high-half tables and logs
  `[WX] kernel image W^X verified (0 violations)` (1789 pages, both boot paths).

## User-space ASLR (`e5a991c`)

Each process gets a random page-aligned slide of its stack top (≤ 16 MB), heap base
and mmap arena base (≤ 32 MB each), from TSC + xorshift64 (layout randomization,
not crypto). `setup_user_args` builds argv/env at the randomized `p->stack_top`.
Gate `-DSECOS_NO_ASLR`. M16 argv / M19 fork unchanged.
**Not randomized**: the ELF base (user ELFs are `ET_EXEC`; needs PIE) and the
kernel text (see scope notes).

## WPA2 association core (`7ee71d1`)

On top of M38's PBKDF2/AES: AES-128 inverse cipher, RFC 3394 key wrap/unwrap (GTK),
the 802.11 PRF (HMAC-SHA1), PTK derivation, EAPOL-Key MIC (`crypto/wpa2_eapol.c`)
and a transport-agnostic 4-way handshake supplicant (`net/wpa2_supplicant.c`).
Boot KATs: RFC 3394 §4.1 vector + a **synthetic handshake** (a stub authenticator
drives msg1..msg4; asserts PTK agreement, msg2 MIC, GTK recovery) — all PASS. The
supplicant is the integration point the radio will feed once frames decode.

## POSIX shell-from-source foundation (`0ca4e0a`, `d1bd579`)

- **Syscalls 49–54**: `SYS_DUP2`, `SYS_DUP`, `SYS_CHDIR`, `SYS_GETCWD`,
  `SYS_IOCTL`, `SYS_GETPPID`. Per-process `cwd` (fork-inherited); `ksys_open`
  resolves relative paths (`proc_resolve_path` normalizes `.`/`..`/`//`). dup/dup2
  keep pipe refcounts right (`dup2(pipe_w, 1)` verified).
- **ioctl**: `TCGETS`/`TCSETS` (cooked-TTY model; toggles `g_tty_canon`/
  `g_tty_echo`), `TIOCGWINSZ` (80×25), `TIOCG/SPGRP`.
- **libc**: `<termios.h>` (`tcgetattr`/`tcsetattr`/`cfmakeraw`), a real `environ`
  + `getenv`/`setenv`/`unsetenv`/`putenv`, `execve`/`execv`/`execvp` **emulated as
  spawn + waitpid + `_exit`**, single-user identity (`getuid`… → 0), `umask`,
  `gettimeofday` (uptime-based), `fcntl` (`F_DUPFD`/`F_GETFL`/`F_SETFL`/…),
  `<sys/time.h>`.
- Demo gate `M39_POSIX_DEMO` (`user/m39_posix.c`) validates every piece ring-3.
- `docs/BASH_PORT.md`: gap analysis of bash 5.2 + staged plan.

## GNU bash 5.2 from source (`2881cf4`, `8762198`, `e66a57f`)

- **Build** (`tools/port-bash.sh`, `make port-bash`): build bash natively once to
  generate derived sources (`y.tab.c`, `builtins/*.c`, `version.h`), then
  cross-compile all 140 objects against SecOS's freestanding libc with
  `-nostdinc`. `user/port-include/` stubs missing system headers;
  `user/bash_port.h` is force-included (POSIX types/macros); `user/bash_compat.c`
  provides ~60 link-time shims (sigaction, root `getpw*`/`getgr*`, unlimited
  `getrlimit`, `times`, `mkstemp`, locale no-ops, `bash_waitpid`…). `config.h`
  patched to disable wide-char/regex/select/locale/dlopen; `--without-readline
  --enable-minimal-config`. Embedded signed as `crypto/user_bash_elf.h` (548 KB).
  Gate `M39_BASH_DEMO`.
- **Fork/pipe bug under bash — two real kernel bugs** (`8762198`):
  1. *Eager zombie reaping lost exit status*: `process_reap_one` freed any zombie
     immediately, so a parent that forked and kept running raced the reaper and its
     `SYS_WAIT(pid)` returned -1 → bash `abort()`. Zombies now persist until the
     parent collects the status (`process_t.collected`), or are reaped when
     orphaned / `ppid==0`.
  2. *No `waitpid(-1)`*: new **`SYS_WAITANY` (55)** — any collectable zombie child,
     `WNOHANG`, `-ECHILD`, or block (woken by `sched_wake_parent_waitany`).
  Result: pipelines, subshells, functions, `case`, loops all correct; `[EXC]` now
  logs CR2.
- **Interactive bash + boot into bash** (`e66a57f`): libc wrappers map negative
  returns to `errno`; `struct secos_stat` gains a stable `st_ino` (inode pointer) +
  `st_dev`/`st_blocks` (bash's getcwd tree-walk); `stat`/`lstat` cwd-relative;
  **`SYS_FSTAT` (56)** returns the fd's real type. The embedded bash is installed
  to `/bin/bash` at boot and launched `run /bin/bash -i`; the kernel shell is the
  recovery fallback when bash exits. Spawn buffers 64 KB → 1 MB. Gate
  `-DSECOS_NO_BASH` drops it. Note: serial input drops the first char of a line
  (QEMU timing); a PS/2 keyboard is unaffected.

## ath9k_hw — upstream Linux driver ported as-is (AR9565)

Instead of writing the radio bring-up from scratch, the upstream Linux `ath9k_hw`
layer is compiled unmodified against a reusable **Linux kernel-API compat shim**.

- **Bring-up steps on the real chip** (`4af78bd`, `c9351cf`, `ce877b6`): OTP read +
  `wifi diag` register dump; AR9300 power-on wake + RTC reset; the real MAC read
  from OTP.
- **Port infrastructure** (`b215829`, `def4b16`, `74d11b9`, `49d415c`):
  `drivers/ath9k_port/compat/` (~50 header stubs: types, io, bitops, spinlock,
  list, atomic, byteorder, minimal cfg80211/mac80211); `ath9k_glue.c` supplies
  ~40 link-time kernel symbols; `tools/port-ath9k.sh` fetches + cross-compiles the
  hw files (+ `ani.c` later) → prebuilt `drivers/ath9k_port/ath9k_hw.o`
  (committed with `git add -f`).
- **Linked into the kernel** (`64b4233`, `03e9dba`): bridge `ath9k_secos.c` wires
  `reg_ops` to SecOS MMIO, allocates `struct ath_hw`, calls the real
  `ath9k_hw_init`. Shell `wifi up`. Inert until invoked.
- **RX bring-up on the ASUS** (main, after `03e9dba`): `wifi chan <n>`
  (`ath9k_hw_reset`), `wifi scan` (EDMA RX over ch 1–13), calibration driven to
  completion (`a64acf4`), real ANI ported (`616afb9`), `AH_USE_EEPROM` + no-EEPROM
  `eeprom_read` for the OTP path, **BT/WLAN RX antenna diversity flag**
  (`fb72ffd` → heard frames 4 → 38 per sweep), `wifi regdump` (`53f6dd1`).

**Status — PARKED at the RX CRC wall.** Frames are received via DMA but fail CRC
(`rs_status=1`), with a noise floor ~20 dB too high: classic over-gain. Alpine
Linux scans and connects on the same ASUS, so the fault is in SecOS's minimal
bring-up. Next datapoint when resumed: `wifi up; wifi chan 6; wifi regdump` to
check the selected RX gain table. TX, auth/assoc MLME, then the (ready) WPA2
supplicant and DHCP remain. The ported driver runs **in ring 0**, not in Driver
Space — moving it to ring 3 is a later discussion.

## Honest scope notes

- **Kernel KASLR: deferred, not shipped.** Relocating kernel text with
  `-mcmodel=kernel` interacts with measured boot and both boot paths; too risky to
  validate blind on real HW. User ASLR shipped instead; W^X already removes the
  executable-alias surface.
- **SMAP: opt-in only** (`-DSECOS_SMAP`). The audit found the read/write/send/recv
  fast paths pass user buffers straight to vfs/pipe/socket; they need
  bounce-buffering before CR4.SMAP can be on by default. Sigframe + argv paths are
  already SMAP-safe.
- **`execve` is emulated** (spawn + wait + exit), so pids change across exec and
  job control under bash is approximate. Env is not inherited across it.
- **Raw-mode TTY not wired**: `TCSETS` flips `g_tty_canon`/`g_tty_echo`, but
  `kernel/tty.c` does not consult them yet — the console is always cooked.
- **ath9k radio**: RX decode wall (above); real-HW-only work, paused.
