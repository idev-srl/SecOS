# M24 — Networking (NIC drivers + full TCP/IP stack)

**State: DONE — all four waves complete and verified in QEMU.** L2/L3 (`ping`)
+ **UDP/DHCP/DNS** + **TCP** (active & passive open) + **BSD sockets gated by
`CAP_NET`** + **MSI-X/NAPI RX** (hybrid). Live-verified against QEMU SLIRP:
DHCP lease, DNS resolution, and a real HTTP GET (2435 bytes) all succeed; the
CAP_NET gate refuses sockets to unprivileged signed programs. Self-test
**122/122** (the net stack is inert without a NIC, so CI is unaffected).

## Design

`net/net.h` is the stable contract (like `block_dev_t` for storage):
- `net_dev_t` — a NIC: `mac`, `transmit(frame,len)`, `poll()` (NAPI-style RX
  drain), `ip/netmask/gateway/dns`, `pci`.
- `net_register_dev` / `net_rx` (driver → stack) / `net_request_irq` (MSI-X
  preferred for 2.5GbE+, INTx, else timer-tick polling — currently polling) /
  `net_tick` (timer-driven poll + protocol timers).
- Protocol entry points: `eth_input`/`eth_send`, `arp_*`, `ipv4_*`, `icmp_*`,
  plus `htons/ntohs/htonl/ntohl` and `net_checksum`.

### NIC drivers
- **drivers/e1000.c** (Intel 82540EM, `8086:100E`) — the reference/tested driver.
  Legacy RX/TX descriptor rings (static DMA via `kvirt_to_phys`), polled drain.
- **drivers/e1000e.c** (82574L `8086:10D3` + I217/I218/I219 family) — ⚠️ not yet
  tested (QEMU's e1000e needs the full stack).
- **drivers/vmxnet3.c** (VMware `15AD:07B0`) — ⚠️ not testable in QEMU (no model);
  validate on VMware.
- **drivers/igc.c** (Intel I225/I226 **2.5 GbE**) — ⚠️ not emulated by QEMU;
  validate on real 2.5GbE hardware.

Each is probed at boot by `net_init`; all are no-ops when their device is absent,
so the build is inert without a NIC (the self-tests are unaffected).

### Stack
Ethernet II framing + demux; ARP (cache + request/reply, passive lookup); IPv4
in/out (no fragmentation, gateway routing); ICMP echo (reply to requests, count
replies). Shell commands `netinfo` and `ping [ip]`.

## Verification

**`ping` works from the shell** (QEMU `-netdev user -device e1000`):
```
secos:/$ ping
PING 10.0.2.2 ...
[NET] ARP resolved gateway
[ICMP] echo reply from 0x...0202000A      (10.0.2.2)
[NET] PING OK
```
The full path is exercised: ARP request/reply, IPv4+ICMP echo request, and the
echo reply received and matched. TX was independently confirmed via a
`filter-dump` pcap (`Request who-has 10.0.2.2` → `Reply 10.0.2.2 is-at ...`).

**Gotcha found:** RX only works when the test runs in the **shell/idle context**
(the idle task `hlt`s between timer ticks, which yields the vCPU to QEMU's main
loop so received DMA actually lands; `net_tick` then polls the ring). An early
self-test that **busy-spun** during `kernel_main` (before the scheduler/idle was
established) never yielded, so QEMU never delivered RX and `GPRC` stayed 0 — this
looked like an RX bug but was a polling/yield artifact. The auto-ping was removed
from boot; use the `ping` shell command (which runs in the idle context).

## Decisions (locked with the user)
- NICs: **e1000 + e1000e + vmxnet3 + igc (2.5GbE)** — all four.
- IRQ: **MSI-X + NAPI** is the target for 2.5GbE+ (INTx fallback); the M22 MSI-X
  plumbing is the basis. Currently the RX path is **timer-tick polling** (the
  contract is identical — drivers only provide `poll()`), with MSI-X as the
  performance upgrade once RX is solid.
- Socket security: a **`CAP_NET`** capability in the signed manifest (general, not
  per-port/protocol) — to be added with the socket API (no per-port rules).

## Wave 1 — UDP + DHCP + DNS (done)

- **`net/udp.c`** — a port-binding table over IPv4. `udp_input()` (the weak hook
  `ipv4.c` already calls) demuxes by destination port to a registered callback;
  `udp_send()` prepends the 8-byte header and computes the pseudo-header checksum.
  `udp_bind/udp_unbind/udp_ephemeral_port` back DHCP, DNS and the socket layer.
- **`net/dhcp.c`** — a four-way DISCOVER/OFFER/REQUEST/ACK client over UDP 68→67
  (broadcast). Runs synchronously from the shell/idle context: it broadcasts, then
  spins on `hlt` so the timer tick drives RX (the same trick as `ping`). On ACK it
  writes `ip/netmask/gateway/dns` into the `net_dev_t`. `ipv4_send()` gained a
  broadcast path (255.255.255.255 / subnet directed → Ethernet broadcast, no ARP)
  so DHCP works before the IP is configured. **Bug fixed:** the BOOTP `xid` is an
  opaque token written big-endian but was read back little-endian, so every OFFER
  was rejected and the client retransmitted forever — read it back big-endian.
- **`net/dns.c`** — a recursive A-record client over UDP 53 to `dev->dns`. Encodes
  the QNAME, parses answers (handles name-compression pointers), returns the first
  A record.
- Shell: `dhcp`, `nslookup <host>`, `udpsend <ip> <port> <text>`.

```
secos:/$ dhcp
dhcp: OK  IP 10.0.2.15  GW 10.0.2.2  DNS 10.0.2.3
secos:/$ nslookup example.com
example.com -> 104.20.23.154
```

## Wave 2 — TCP (done)

- **`net/tcp.c`** — connection table + full open/close state machine
  (LISTEN/SYN-SENT/SYN-RCVD/ESTABLISHED/FIN-WAIT-1/2/CLOSE-WAIT/CLOSING/LAST-ACK/
  TIME-WAIT), cumulative ACKs, a sliding send window, in-order receive buffering
  (8 KB rings), MSS option on SYN, and a retransmit timer driven from `net_tick()`
  (`tcp_tick`). Active open (`tcp_connect`) **and** passive open
  (`tcp_listen`/`tcp_accept_ready` with a small backlog of children). Out-of-order
  segments are dropped and re-ACKed (the peer retransmits) — correct, if not fast.
- Blocking convenience wrappers (`tcp_connect`/`tcp_send_all`/`tcp_recv_block`/
  `tcp_close`) spin on `hlt`; the non-blocking core (`tcp_write`/`tcp_read`/…)
  backs the socket layer.
- Shell: `tcptest <ip> <port>` does an HTTP GET. Verified against a host
  `python3 -m http.server` via SLIRP — **2435 bytes** of a real HTTP/1.0 response
  received (3-way handshake → data → FIN teardown).

## Wave 3 — BSD sockets + CAP_NET (done)

- **`net/socket.c`** + `net/socket.h` — a kernel-owned socket table. TCP sockets
  wrap a `tcp_conn_t`; UDP sockets bind a port whose callback enqueues datagrams
  into a per-socket ring. Blocking calls (connect/accept/recv) spin on `hlt` — the
  timer ISR runs `net_tick` even during a ring-0 syscall, so RX is delivered.
- Syscalls **21–30** (`socket/connect/bind/listen/accept/send/recv/sendto/
  recvfrom/sockclose`); libc wrappers in `user/libsecos.c`. `sendto`/`recvfrom`
  pass a `struct secos_sockaddr` pointer (fits the 5-arg ABI).
- **`CAP_NET`** — a single, general network capability, bit 4 of the signed
  `.note.secos` manifest `flags` (`MANIFEST_FLAG_CAP_NET`). `process_create_from_elf`
  records it (`process_t.cap_net`); the socket dispatcher refuses **every** socket
  syscall (`-EPERM`-ish) when it's absent. Signature-rooted: a program can't grant
  itself the cap. `process_destroy` closes a dead process's sockets.
- Demo gate **`M24_NET_DEMO`** (`user/m24_net.c`, signed two ways): the CAP_NET
  build gets a socket (`[m24net] socket OK`); the same program signed **without**
  CAP_NET is refused at the first `socket()` (`[NET] socket syscall denied`,
  `[m24net] socket DENIED`). Deterministic — no NIC required.

## Wave 4 — MSI-X / NAPI RX (done, hybrid)

- `net_request_irq()` gained a gated MSI-X path (`-DNET_USE_MSIX`, **off by
  default** — the default build stays byte-for-byte polled). It enables the LAPIC,
  installs IDT vector **0x42** (`isr_net` → `net_irq_handler`, NAPI: ack NIC →
  drain ring → `lapic_eoi`), and programs the device via the M22
  `pci_enable_msix`/`pci_enable_msi`. Drivers add optional `irq_enable`/`irq_ack`
  hooks (e1000 + e1000e implement them; e1000e also programs the 82574 **IVAR** to
  route the RxQ0 cause to MSI-X table entry 0).
- **Validated in QEMU** with `-device e1000e -DNET_USE_MSIX`: the ISR fires
  (`[NET] IRQ fired`), the ARP reply is delivered via the interrupt, and DHCP +
  ping + DNS all succeed in `mode=msix`.
- **Hybrid NAPI:** MSI-X mode also keeps a timer-tick poll backstop. The interrupt
  gives low-latency RX wakeups; the watchdog poll guarantees completeness if a
  NIC's interrupt re-arm semantics drop an edge (standard production-driver
  practice). On a NIC without MSI-X (QEMU's legacy e1000) it logs `no MSI-X/MSI;
  staying polled` and falls back cleanly.

## Validated on real VMware (2026-06-19)

The full stack runs on **VMware Workstation against a live bridged LAN** (not just
QEMU SLIRP), with the NIC bound by the e1000-family driver (VMware MAC `00:0c:29`):
- **DHCP** lease from the physical router (`192.168.1.18`, gw `.1`, dns `.224`).
- **ICMP** ping to the real gateway → reply.
- **DNS** `google.it → 142.251.141.227` via the LAN DNS server.
- **TCP to the public internet** — HTTP GET to Google `:80` → `HTTP/1.0 404`
  (1716 bytes; full handshake → data → teardown).
- **TCP to a LAN device** — HTTP GET to a terminal server `192.168.1.96:80` →
  `HTTP/1.1 200 OK`, ~8 KB multi-segment response reassembled in order.
