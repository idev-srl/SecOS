# M24 — Networking (NIC drivers + TCP/IP stack foundation)

**State:** L2/L3 done — **`ping` works** (host↔VM, full ARP→IPv4→ICMP round-trip).
A NIC driver contract, four NIC drivers, and the Ethernet/ARP/IPv4/ICMP stack.
e1000 TX+RX verified in QEMU. UDP/DHCP/DNS, TCP, and the socket API + `CAP_NET`
are the next waves.

## Design

`net/net.h` is the stable contract (like `block_dev_t` for storage):
- `net_dev_t` — a NIC: `mac`, `transmit(frame,len)`, `poll()` (NAPI-style RX
  drain), `ip/netmask/gateway/dns`, `pci`.
- `net_register_dev` / `net_rx` (driver → stack) / `net_request_irq` (MSI-X
  preferred for 2.5GbE+, INTx, else timer-tick polling — currently polling) /
  `net_tick` (timer-driven poll + protocol timers).
- Protocol entry points: `eth_input`/`eth_send`, `arp_*`, `ipv4_*`, `icmp_*`,
  plus `htons/ntohs/htonl/ntohl` and `net_checksum`.

### NIC drivers
- **drivers/e1000.c** (Intel 82540EM, `8086:100E`) — the reference/tested driver.
  Legacy RX/TX descriptor rings (static DMA via `kvirt_to_phys`), polled drain.
- **drivers/e1000e.c** (82574L `8086:10D3` + I217/I218/I219 family) — ⚠️ not yet
  tested (QEMU's e1000e needs the full stack).
- **drivers/vmxnet3.c** (VMware `15AD:07B0`) — ⚠️ not testable in QEMU (no model);
  validate on VMware.
- **drivers/igc.c** (Intel I225/I226 **2.5 GbE**) — ⚠️ not emulated by QEMU;
  validate on real 2.5GbE hardware.

Each is probed at boot by `net_init`; all are no-ops when their device is absent,
so the build is inert without a NIC (the self-tests are unaffected).

### Stack
Ethernet II framing + demux; ARP (cache + request/reply, passive lookup); IPv4
in/out (no fragmentation, gateway routing); ICMP echo (reply to requests, count
replies). Shell commands `netinfo` and `ping [ip]`.

## Verification

**`ping` works from the shell** (QEMU `-netdev user -device e1000`):
```
secos:/$ ping
PING 10.0.2.2 ...
[NET] ARP resolved gateway
[ICMP] echo reply from 0x...0202000A      (10.0.2.2)
[NET] PING OK
```
The full path is exercised: ARP request/reply, IPv4+ICMP echo request, and the
echo reply received and matched. TX was independently confirmed via a
`filter-dump` pcap (`Request who-has 10.0.2.2` → `Reply 10.0.2.2 is-at ...`).

**Gotcha found:** RX only works when the test runs in the **shell/idle context**
(the idle task `hlt`s between timer ticks, which yields the vCPU to QEMU's main
loop so received DMA actually lands; `net_tick` then polls the ring). An early
self-test that **busy-spun** during `kernel_main` (before the scheduler/idle was
established) never yielded, so QEMU never delivered RX and `GPRC` stayed 0 — this
looked like an RX bug but was a polling/yield artifact. The auto-ping was removed
from boot; use the `ping` shell command (which runs in the idle context).

## Decisions (locked with the user)
- NICs: **e1000 + e1000e + vmxnet3 + igc (2.5GbE)** — all four.
- IRQ: **MSI-X + NAPI** is the target for 2.5GbE+ (INTx fallback); the M22 MSI-X
  plumbing is the basis. Currently the RX path is **timer-tick polling** (the
  contract is identical — drivers only provide `poll()`), with MSI-X as the
  performance upgrade once RX is solid.
- Socket security: a **`CAP_NET`** capability in the signed manifest (general, not
  per-port/protocol) — to be added with the socket API (no per-port rules).
