# M10 — Storage & persistence (virtio-blk + FAT32/ext2/ext4 + run from disk)

**State:** done. Self-test harness 38/38 (was 14/14; +24 M10 assertions across
fat32/ext2/ext4). Demos/gate off by default; normal boot reaches the shell.

## Goal

Load programs and persist data on a real disk: a virtio-blk driver, read-write
filesystems through the VFS, and the ability to run a **signed** program loaded
from the disk image.

## What landed

### Block layer + virtio-blk (`drivers/pci.*`, `drivers/virtio_blk.*`, `fs/block.*`)
- Minimal PCI config-space access via the legacy `0xCF8`/`0xCFC` mechanism
  (`pci_find`, BAR0 I/O base, enable I/O + bus-master).
- virtio-blk driver targeting QEMU's **legacy/transitional** virtio-blk-pci
  (vendor `0x1AF4`, device `0x1001`) over the BAR0 I/O region. A single split
  virtqueue lives in a **page-aligned static buffer**: the kernel is
  identity-mapped (phys==virt below 128 MB), so the buffer's virtual address is
  the guest-physical address handed to the device. Completion is **polled** on
  the used ring (no IRQ). DMA always targets an internal **bounce buffer**
  (physically contiguous, in the kernel image), so caller buffers need no
  contiguity guarantee. Registers block device `vda`. Read **and** write
  verified (write+readback in-kernel).
- `block_dev_t` gains a `write()` op; `block_read`/`block_write` wrappers.

### VFS multi-mount (`fs/vfs.*`)
- Single-root → **multi-mount** with longest-prefix routing. ramfs stays root
  `/`; the disk FS mounts at `/mnt`. The mount-relative path (rooted at `/`) is
  handed to the underlying FS ops. `vfs_lookup` stamps `inode->ops` with the
  owning mount so read/write route correctly.

### FAT32 read-write (`fs/fat32.c`, full rewrite from stub)
- BPB parse, FAT cluster-chain r/w, cluster alloc/free, 8.3 directory entry
  scan/create, file read/write(grow), create, mkdir, remove, truncate, rename.
- Cross-validated: a file written by the kernel is read back by host `mtools`.

### ext2 / ext4 read-write (`fs/ext2.c`, full rewrite from stub)
- One driver handles both: block mapping branches on the per-inode **EXTENTS**
  flag (ext4 extent tree) vs. classic **indirect blocks** (ext2). Superblock +
  group descriptors, inode table, block/inode bitmaps with consistent
  free-count maintenance, directory linked-list entries.
- ext2: direct + single/double indirect (read), direct + single indirect
  (write). ext4: inline depth-0 **extent** read+write (coalescing, up to 4
  inline extents), 64-bit descriptors.
- Cross-validated: kernel writes are read by host `debugfs` and **`e2fsck -fn`
  is clean** (Pass 1–5, no errors) for both ext2 and ext4 images.

### Run a signed program from disk (`SYS_SPAWN`/`SYS_WAIT`, shell `run`)
- `SYS_SPAWN(path)` / `SYS_WAIT(pid)` syscalls (numbers 8/9) + `ksys_spawn`
  (VFS read → `process_create_from_elf`, signing gate enforced) / `ksys_wait`.
- The interactive shell now runs as the **scheduler idle task**: `run <path>`
  spawns a ring-3 process; the timer preempts idle (shell) into it; on
  `SYS_EXIT` the scheduler returns to the saved idle context, so the shell
  regains control. Required one scheduler change: **save the idle context on
  preemption** (it was previously treated as restart-only).
- Gate (`M10_RUN_DEMO`): write the embedded signed `hello.elf` to disk, refuse a
  tampered copy, then `run /mnt/hello.elf` — proving write→read→verify→ring-3
  →exit end-to-end, asserted on debugcon for all three filesystems.

## Scope decisions (user-confirmed)
- Target filesystems = **FAT32, ext2 AND ext4** (read-write).
- **ext4 = no-journal v0**: test image `mkfs.ext4 -O ^has_journal,^metadata_csum`.
  Extents + 64-bit supported; JBD2 journaling and `metadata_csum` checksums are
  deferred (a later hardening milestone).
- Disk FS mounts at a dedicated **`/mnt`** (ramfs stays root).

## Build / test / run
```bash
make disk-fat32            # 64MB FAT32 test image (also disk-ext2 / disk-ext4)
make run-disk              # boot + attach -drive if=virtio (debugcon to stdio)
make iso CFLAGS_EXTRA=-DM10_RUN_DEMO=1   # the run-from-disk gate build
tools/selftest.sh          # 38/38 (M4 + crypto + M7 + M8 + M9 + M10×3 FS)
```
Note: with a disk attached, QEMU must be told to **`-boot d`** (boot the CD-ROM),
otherwise the BIOS tries to boot the data disk.

## Gotchas
- `make` does not track `CFLAGS_EXTRA` changes — `make clean` (or touch the
  source) when toggling `-D…` demo flags, or you get a stale kernel.bin.
- The virtqueue/bounce buffers rely on the identity map (kernel < 128 MB); this
  must be revisited if/when the kernel moves higher-half (M12).
- ext4 writes do not update `metadata_csum`; images must disable it for now.
