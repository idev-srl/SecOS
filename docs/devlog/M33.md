# M33 — Full ext4 root + metadata_csum (read-write)

**Goal:** make a real ext4 volume usable as the persistent root, including a
default-`mkfs.ext4` volume that carries `metadata_csum` — and keep it
**e2fsck-clean** after SecOS writes to it.

## What shipped

- **ext4 persistent root.** `ext2_mount_root` already mounted any volume the
  driver supports (it reads ext4 extents/64-bit/journal). New `sysdisk-ext4`
  Makefile target builds an ext4 (journal + extents + 64-bit) system disk; the
  M27 write-journaling engages, so the root's metadata writes are crash-atomic.
  Verified: SecOS mounts it, installs coreutils, writes `/VERSION`, `e2fsck -fn`
  clean.

- **metadata_csum (crc32c) read-write** in `fs/ext2.c`. Modern `mkfs.ext4`
  enables `metadata_csum` by default, so supporting it is what lets a *normal*
  ext4 disk be used. Every mutating metadata write now refreshes its crc32c:
  - **superblock** `s_checksum` (seed `~0`),
  - **group descriptor** `bg_checksum` + **block/inode bitmap** checksums
    (centralised in `gd_write`/`gd_finalize_csum`), which also recompute
    `bg_itable_unused` exactly from the inode bitmap and clear
    `EXT4_BG_{INODE,BLOCK}_UNINIT` so e2fsck's uninit_bg accounting agrees,
  - **inode** `i_checksum_lo`/`i_checksum_hi`,
  - **directory blocks** — the 12-byte `ext4_dir_entry_tail` at `blocksize-12`;
    `dir_lookup`/`dir_add`/`dir_remove`/`mkdir` are tail-aware via
    `dir_entry_limit()`.
  - per-inode seed = `crc32c(crc32c(s_csum_seed, ino), gen)`; `s_csum_seed` =
    `s_checksum_seed` (if `INCOMPAT_CSUM_SEED`) else `crc32c(~0, uuid)`.

  Every hook is gated on `g_csum`, so non-csum ext2/ext4 volumes (M10/M26/M27)
  are byte-for-byte unchanged.

## Method note

All six checksum formulas were validated **byte-for-byte against a real
`mkfs.ext4` image in Python** (superblock, group desc, inode lo/hi, directory
block, block bitmap, inode bitmap) *before* writing the C — this caught the exact
field offsets and seed derivation up front.

## Verified

- `make sysdisk-ext4-csum` → boot → mkdir + nested create + write + rm →
  `e2fsck -fn` **clean** (added as an M33 case in `tools/selftest.sh`).
- Non-csum ext2/ext4 paths unaffected; both smoke paths PASS.

## Gotcha

The "mkdir fails on the disk root" scare during bring-up was a **test-harness
timing artifact** (piped serial input consumed before the shell was ready), not a
driver bug — mkdir/create/nested all work on both ext2 and ext4 roots.
