# M32 — Signed packages + service manager (Phase K)

Closes Phase K (userland & near self-hosting). M32 extends the M9 Ed25519 signing
root from *executables* to *distribution*: a signed package, and a supervised init.

## Signed packages (`.spkg`)

A package bundles files + directories to install into the VFS, sealed with the
same key as code. **Install = verify the signature, then unpack** — a forged or
tampered package installs nothing.

- **Format** (`tools/secos-pkg`, host): a 64-byte header (`magic "SECOSPKG"`,
  version, file count, sig offset), a table of 152-byte entries (`path[128]`,
  mode, type, data offset/size), the file blobs, and a 64-byte Ed25519 signature
  at the end. The digest is **SHA-256 over the whole file with the 64 sig bytes
  zeroed** — the exact rule used for ELF `QSIG`, so the kernel reuses its verify
  path. Signed with the dev key from `secos_signlib` (`tools/secos-pkg create
  OUT.spkg SRC:/dest [...] [--mkdir /d]`; `verify` re-checks).
- **Kernel** (`kernel/pkg.c`): `pkg_install(buf, len)` checks the magic, verifies
  the Ed25519 signature against `secos_trusted_pubkey` (`sha256` + `ed25519_verify`),
  bounds-checks every entry, then `vfs_mkdir`/`vfs_create`s them. Returns the entry
  count, or <0 (nothing installed) on a bad/short/forged package.
- **Shell**: `pkg install <file.spkg>` reads a package from the VFS and installs it.

Verified (gate `M32_PKG_DEMO`): the signed test package installs (`/etc/pkg-motd.txt`
+ `/opt/pkgdir/info.txt`), a **one-byte-tampered copy is REFUSED**
(`[PKG] SIGNATURE INVALID`), and `cat /etc/pkg-motd.txt` shows the delivered
content. `/bin/cat` reads it back; `/bin/ls /opt/pkgdir` lists the unpacked dir.

## init / service manager

`user/init.c` is a minimal **supervised init**: it spawns a table of signed
services and restarts each on exit, up to a per-service limit, then gives up — a
bounded loop (this OS has no Ctrl-C yet) that proves the supervision cycle and
exits cleanly. Because every service is a signed ELF, the trust boundary holds:
init can only launch what the key blessed. `user/svc_demo.c` is a trivial service
(announce → work → exit). Both are installed to `/bin` (`/bin/init`, `/bin/svc`).

Verified: `run /bin/init` starts `/bin/svc`, which exits, and init restarts it
twice (`[init] restart 1/2 …`, `[svc] service started` ×3) before
`[init] all services stopped`.

## Phase K status

The libc (M31a), file-management syscalls + coreutils (M31b), signed packages and
a supervised init (M32) are in. **Open for full self-hosting** (future): a fuller
libc (`%f`, more of stdio/locale), `getcwd`/cwd + environment, an external port
built from source (lua/sqlite — needs `setjmp`/`longjmp` + math), and a real PID-1
init wired into boot. Tracked in `TASKS.md`.
