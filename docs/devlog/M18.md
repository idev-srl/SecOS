# M18 — Dynamic memory: mmap / munmap / mprotect / brk + user malloc

**State:** done. Self-test harness **84/84** (was 75/75; +9 M18 assertions).
Demo gated behind `M18_MEM_DEMO`, off by default. First milestone of Phase G
(VM completeness).

## Goal

Give user programs a real dynamic-memory API on top of the M14 demand-paging
VMA framework: a growable heap (`brk`/`sbrk`) with a libc `malloc`/`free`, plus
`mmap`/`munmap`/`mprotect` for anonymous regions — all W^X-enforced and bounded
by the signed manifest's `max_mem`.

## What landed

### VMA set upgrades — `mm/vma.{c,h}`
- `VMA_MAX` 16 → **64** (mmap/heap create many regions).
- **Tombstones** (`VMA_TYPE_NONE`): `vma_remove` marks a slot dead instead of
  compacting, so existing VMA pointers/indices stay stable; `vma_add` reuses a
  tombstone or appends. New helpers: `vma_find_mut`, `vma_overlaps`,
  `vma_total_bytes` (live reserved footprint, for `max_mem`).

### Address-space layout — `mm/vmm.h`
Carved the user range: `USER_HEAP_BASE` (10 GB, brk grows up) and
`USER_MMAP_BASE`..`USER_MMAP_END` (12 GB arena, below the stack guard band).

### Page-protection primitive — `mm/vmm.c`
`vmm_protect_in_space(space, va, flags)` rewrites a **present** PTE's flags while
keeping its frame, enforces W^X (`-5` on W+X), and `invlpg`s the entry. Not-present
pages are left to the VMA flags on their next fault.

### The four syscalls — `kernel/syscall.c` (`SYS_BRK/MMAP/MUNMAP/MPROTECT` = 16/14/15/17)
All operate on the current process's VMA set; pages stay demand-faulted (the M14
#PF path), so these only manipulate VMAs and already-present PTEs.
- **`brk`** grows/shrinks a single ANON heap VMA `[USER_HEAP_BASE, brk_cur)`; grow
  is refused if it would exceed `mem_limit`; shrink unmaps the freed pages.
- **`mmap`** (anonymous only in M18) bump-allocates from `mmap_next`, adds an ANON
  VMA with `prot`→flags, rejects `W+X`, and honors `mem_limit`.
- **`munmap`** unmaps present pages and trims/removes/splits the covered VMAs.
- **`mprotect`** rejects `W+X`, updates whole-VMA flags in range, and re-protects
  the present PTEs via `vmm_protect_in_space`.

`process_t` gains `brk_start`/`brk_cur`/`mmap_next`/`mem_limit` (the last mirrors
the signed manifest `max_mem`, so runtime growth is bounded by the same trust
root that M13 enforces at load).

### libc — `user/libsecos.{c,h}`
`mmap`/`munmap`/`mprotect`/`sbrk`/`brk_set` wrappers plus a minimal first-fit
`malloc`/`free` over `sbrk` (block header + singly-linked free list; reuse, no
coalescing yet). `PROT_*`/`MAP_*` constants match the kernel ABI.

### Demo + harness — `kernel/kernel.c` (`M18_MEM_DEMO`), `user/m18_mem.c`
One signed program proves the lot: a multi-page `malloc` (forces `sbrk` growth +
demand faults) round-trips; `free` + `malloc` reuses the block; anonymous `mmap`
is read-write; `W+X` is refused by both `mmap` and `mprotect`; `mprotect` to
read-only keeps reads working; finally a **write to the read-only page terminates
the process** (`[KILL]`, reusing M15), proving `mprotect` actually enforces — and
the kernel survives. Nine assertions.

## Things worth noting

- **Demand paging does the heavy lifting:** `brk`/`mmap` never allocate frames —
  they only register VMAs. The M14 fault handler zero-fills pages on first touch,
  so a 12 KB `malloc` that's only partially written costs only the touched pages.
- **W^X is enforced at three layers:** the syscall rejects `W+X` prot up front,
  `prot_to_flags` always sets NX unless EXEC is requested, and `vmm_map`/
  `vmm_protect_in_space` reject RW-without-NX as a backstop.
- **`max_mem` now bounds runtime growth,** not just load-time footprint — a signed
  program cannot `mmap`/`brk` its way past its manifest limit.
- **mprotect on a partial VMA** updates the present PTEs precisely but applies the
  flag change to whole VMAs only (no VMA split) — a not-yet-faulted page inside a
  partially-mprotected VMA would fault with the old flags. Whole-region mprotect
  (the common case) is exact. Documented limitation; revisit if needed.

## Deferred / next

- **File-backed mmap** (mapping a VFS file) is deferred to **M20** (page cache),
  where the cache provides the shared backing pages.
- **malloc** has no block splitting/coalescing — fine for bring-up; a better
  allocator (or porting one) is userland work.
- **M19** (next): copy-on-write + `fork` — needs a PMM frame refcount; the COW
  write-fault path slots into the same #PF handler.
