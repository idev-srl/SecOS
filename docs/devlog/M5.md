# M5 Devlog — Trapframe Syscall Entry + Kernel-Stack Hardening

## Summary

M5 reworks the syscall entry path so that `INT 0x80` produces the same
canonical register layout as the exception path, and replaces the PID-based
kernel-stack slot scheme with a bounded slot index. No new user-visible
features; this is plumbing that M6/M7 build on.

Relevant commits:
- `cd7a2c4` [M5][Hardening] Replace PID-based kernel stack slots with bounded slot index
- `1074114` [M5.1] Unify syscall entry into trapframe + C syscall_handler

---

## TASK 1 — Bounded kernel-stack slots

Previously a process's kernel stack slot was derived from its PID, which does
not scale and can index out of range. The slot is now a bounded index,
decoupling kernel-stack assignment from the PID value.

Files: `kernel/process.c`, `arch/x86/tss.c` (kernel stack wiring).

## TASK 2 — Unified trapframe syscall entry

The ad-hoc `syscall_entry` stub is replaced by a canonical trapframe-based
entry that mirrors `isr_common`:

- `kernel/trapframe.h` — defines `trapframe_t` (`r15..rax`, `int_no`,
  `err_code`, then the CPU-pushed `rip/cs/rflags/rsp/ss`).
- `arch/x86/syscall_asm.asm` — full GPR save, pushes `int_no = 0x80` and a
  dummy `err_code`, passes the trapframe pointer in `RDI` to
  `syscall_handler()`, then patches `RAX` (return value) back into the
  trapframe before `iretq`.
- `kernel/syscall_trap.c` — `syscall_handler(trapframe_t*)` extracts the ABI
  registers from the trapframe and forwards to the existing
  `syscall_dispatch()` (unchanged). Optional `SYSCALL_DEBUG` logging.
- `Makefile` — adds `kernel/syscall_trap.c` to the build.

The exception handler (`isr_common`) and `syscall_dispatch` are unchanged.
