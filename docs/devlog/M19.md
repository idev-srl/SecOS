# M19 — Copy-on-write fork

**State:** done. Self-test harness **91/91** (was 84/84; +7 M19 assertions).
Demo gated behind `M19_FORK_DEMO`, off by default. Phase G (VM completeness).

## Goal

A real `fork()`: duplicate a process's address space lazily by sharing every
page copy-on-write, so the child gets an independent copy of memory that only
diverges when one side writes. Needs a per-frame reference count and a COW
write-fault path on top of the M14 demand-paging handler.

## What landed

### PMM frame refcounts — `mm/pmm.{c,h}`
A dense `uint16_t frame_refs[]` array (EXTRA references = refcount − 1) placed
right after the bitmap at `_kernel_end`, zero-initialized, and covered by the
protected kernel range. `pmm_share_frame` adds a reference; `pmm_unref_frame`
drops one and returns **1 if the frame is still shared** (don't free) or **0 if it
was the last reference** (the caller frees). The leaf-page frees in
`vmm_unmap_in_space` and `vmm_space_destroy` now route through `pmm_unref_frame`,
so a shared COW frame survives until its last owner releases it.

### COW duplicate of an address space — `mm/vmm.c` `vmm_fork_space`
Creates a fresh user space, then walks the parent's present user leaves: each
frame is **shared** (`pmm_share_frame`); a **writable** page is made read-only +
`VMM_FLAG_COW` (a software PTE bit, 1<<9) in **both** parent and child (so the
first writer copies); a read-only page (code) is shared as-is. The parent TLB is
flushed (its PTEs were mutated and it is the current CR3).

### COW write fault — `mm/vmm.c` `vmm_cow_fault` + the #PF handler
A **write to a present read-only page** now checks the COW bit first: if set, the
writer gets a private copy (`pmm_alloc_frame` + copy via the physmap), drops its
reference to the old frame, and the PTE is rewritten **read-write, COW cleared**.
If the page is not COW, it falls through to the existing fatal path (a genuine
RO-violation → kill, M15).

### fork() — `kernel/process.c` `process_fork`, `kernel/syscall_trap.c`, libc
`SYS_FORK` (18) is handled in `syscall_handler` (it needs the parent's live
trapframe). `process_fork` shallow-copies the PCB, COW-forks the address space,
gives the child its **own** pinned ELF image (FILE-VMA `file_base` pointers are
re-based into the copy) and manifest, a fresh kernel stack + trapframe (`rax=0` so
`fork()` returns 0 in the child), resets blocking/scheduling state, and — for
security — **does not inherit driver privilege** (children are plain users). The
parent gets the child pid. libc `int fork(void)`.

### Demo + harness — `kernel/kernel.c` (`M19_FORK_DEMO`), `user/m19_fork.c`
The signed `m19_fork` fills a static buffer with `'P'`, forks, the child confirms
it **inherited** `'P'`, overwrites it with `'C'` (a COW copy), and exits 7; the
parent `waitpid`s, reads status 7, and confirms its own buffer is still `'P'`
(**COW isolation**). Seven assertions.

## The bug that mattered: intermediate page-table permissions

The first run killed the child on its first stack write *after* a successful COW
copy — the leaf PTE was read-write, yet the write still protection-faulted. Cause:
on x86-64 the effective write permission is the **AND of the RW bit across all
paging levels** (with `CR0.WP=1`). `get_or_create_table` was propagating the
*leaf's* flags to the intermediate PDPT/PD entries, so a COW page mapped with RW
cleared created **read-only intermediate entries** — and flipping the leaf to RW
later couldn't grant write because the level above still lacked RW.

Fix: intermediate entries are now **always** `RW | PRESENT` (USER still propagated
so kernel-range tables stay supervisor). The **leaf PTE is the sole authority** on
write/exec protection — a read-only or NX leaf is still enforced regardless of the
permissive levels above it. This is the standard x86-64 paging discipline and it
also makes the W^X/COW machinery composable.

## Things worth noting

- **Image + manifest are copied, not shared**, so each process owns them and
  `process_destroy` frees them without refcounting; FILE-VMA backing pointers are
  rebased into the child's image copy so lazy text/data faults still work.
- **Driver privilege is dropped on fork** — a forked child of a signed driver is a
  plain user; re-acquiring device capability requires its own signed manifest.
- **Refcount placement**: the dense array is 2 bytes/frame (≈1 MB at 2 GB RAM),
  sharing the low-identity window with the bitmap; fine for test scales.
