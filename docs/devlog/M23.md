# M23 — POSIX filesystem personality (persistent root + /dev + /proc + /sys)

**State:** done. The foundation for compiling open-source Linux software *from
source* (and signing it) for SecOS: a Linux-style filesystem hierarchy with a
**persistent ext2 root**, a **/dev** device namespace, **/proc** and **/sys**
introspection, and the `lseek`/`stat` syscalls + libc wrappers.

## Trust model (the design decision behind /dev)

In SecOS the **Ed25519 signature is the trust boundary**: only signed code runs,
so a signed program is given *ambient authority* over `/dev` like a normal Linux
process — no per-`open()` capability check. **Driver Space stays orthogonal**: a
`/dev/<blk>` read still goes through the kernel's block driver, so exposing block
devices as files does not hand raw hardware to user space. Accepted trade-off:
the signing key becomes the whole perimeter (a signed binary can `dd` a raw
disk), which is fine when you control signing.

## What landed

### VFS: page-cache bypass + mount introspection — `fs/vfs.{c,h}`
- `vfs_fs_ops_t` gains a `flags` field; `VFS_FS_NOCACHE` marks virtual
  filesystems whose contents are generated/dynamic. `ksys_read` reads those
  straight via `->read()` instead of the unified page cache (so `/dev/random` and
  `/proc/uptime` are live, not cached).
- `vfs_mount_count()` / `vfs_mount_info()` for `/proc/mounts`.
- `VFS_MAX_MOUNTS` 4 → 12 (root + /mnt + /dev + /proc + /sys + headroom).

### devfs — `fs/devfs.c` (new), mounted at `/dev`
Char devices `null`, `zero`, `full`, `random`/`urandom` (xorshift64*, **not**
crypto-grade), `console`, `tty`; plus every registered `block_dev_t`
(`vda`/`sda`/`nvme0n1`/`usb0`…) as a **byte-addressed** node over a one-sector
bounce buffer (handles unaligned head/tail). Read-only namespace.

### procfs — `fs/procfs.c` (new), mounted at `/proc`
Generated-on-read text files: `meminfo`, `uptime`, `version`, `cpuinfo`,
`mounts`, `self` (pid/state). Size is recomputed live on each lookup/read.

### sysfs — `fs/sysfs.c` (new), mounted at `/sys`
Minimal block tree: `/sys/block/<dev>/{size,sector_size}` (size in 512-byte
units, Linux convention) + `/sys/version`.

### Syscalls + libc — `kernel/syscall.{c,h}`, `user/libsecos.{c,h}`
`SYS_LSEEK` (19, `SEEK_SET/CUR/END`) and `SYS_STAT` (20, `struct secos_stat`
= `st_size`+`st_mode`). libc `lseek`/`stat` + the `O_*`/`SEEK_*`/`S_IF*` macros.

### Persistent ext2 root — `fs/ext2.c`, `kernel/kernel.c`, `Makefile`
- `ext2_read_super()` extracted; `ext2_mount_root()` mounts an ext2 volume as the
  VFS root **only if it carries the marker file `/.secosroot`** — so a plain ext2
  *data* disk is never silently adopted as root (and the boot self-tests, which
  have no system disk, keep the RAMFS root unchanged).
- Boot probes `vda,sda..sdd,nvme0n1,usb0` for a marked ext2 system disk; if found
  it becomes `/` (and the `/mnt` data mount is skipped — single-root model),
  otherwise the RAMFS root + `/mnt` behaviour is exactly as before.
- `make sysdisk-ext2` / `sysdisk-vmdk` build a system-root image with the FHS
  skeleton (`/bin /etc /dev /proc /sys /tmp /usr /opt /home /lib /root /var`),
  the `/.secosroot` marker, `/etc/secos-release`, `/etc/motd`.

### FHS skeleton + boot wiring — `kernel/kernel.c`
After the root is mounted, the FHS directories are ensured and devfs/procfs/sysfs
are mounted. Boot self-checks log `[M23]` markers (mount results, `/proc/version`,
`/dev` block-node presence, persistent-root device).

## Verification

- Shell: `vls /dev` lists the char + block nodes (`vda` shows its byte size);
  `vls /proc` + `vcat /proc/meminfo`/`/proc/uptime` render live; `vls /sys/block`
  shows the device tree.
- Signed user program `user/m23_fs` (demo gate `M23_FS_DEMO`): from **ring 3** it
  reads `/dev/zero`, writes `/dev/null`, reads `/proc/uptime`, and `stat()`s +
  `lseek()`s a `/dev` block node — all OK, `[m23fs] DONE`, no `[EXC]`. This is the
  headline proof: a signed program uses the Linux-style FS.
- **Persistence**: with an ext2 system disk, boot 1 `vcreate /home/ptest.txt
  persistok`, boot 2 (fresh) `vcat /home/ptest.txt` → `persistok`. The file
  survived the reboot.
- No regression: full self-test 112/112 (marker-gated root adoption keeps every
  CI run on the RAMFS root).

## Shell cleanup

Added POSIX-style commands over the unified VFS with a real working directory
(`kernel/shell.c`): **`ls cd pwd cat touch mkdir rm df free uname`**.
`cwd_resolve()` normalizes `.`/`..`/`//` against `g_cwd`; the prompt now shows the
cwd (`secos:/home$`). These operate on `/`, `/mnt`, `/dev`, `/proc`, `/sys`
uniformly (e.g. `cat /proc/uptime`, `ls /dev`, `df`). The legacy `v*` (VFS) and
`rf*` (RAMFS) commands are kept — init.rc and the self-tests still use
`vls`/`vcat`, and `rf*` remain a RAMFS scratch interface.

## Scope / what's next

This is the **foundation**, not full Linux source-compatibility. Growing that is
a long road, program-by-program:
- **`ioctl`** (deferred): tty/termios, block/device ioctls — many `/dev` programs
  need it.
- A more complete **libc** (musl/newlib port) and a wider **syscall surface**
  (poll/select/fcntl/dup/pipe/signals/threads).
- Per-pid `/proc/<pid>/...` directories; richer `/sys`.
- Optional: a signed-manifest capability to *restrict* a binary's `/dev` access
  (defense-in-depth on top of "signed = trusted").
