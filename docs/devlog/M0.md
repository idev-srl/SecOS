## Hotfix Session: Full UEFI Boot Chain Debug (branch debug/uefi-unsupported)

### Fix 1: Stale elf_load.o — Makefile Header Dependency
- **Sintomo**: crash `#GP` a 0xAFAFAFAF (poisoned memory), `BootServices` letto a offset errato
- **Causa**: `uefi/elf_load.o` compilato prima delle correzioni alle struct in `efi.h`, Makefile non aveva dipendenza sull'header
- **Fix**: aggiunta regola `uefi/%.o: uefi/%.c uefi/efi.h` in `Makefile`; rebuild forzato con `rm -f uefi/elf_load.o uefi/boot.o && make uefi`
- **Proof**: `objdump -d uefi/elf_load.o` mostra `mov 0x60(%rdi),%rax` (BootServices) e `call *0x140(%rax)` (LocateProtocol) ✓

### Fix 2: kernel.elf assente nell'immagine ESP
- **Sintomo**: `ELF load: 0x8000000000000004` = `EFI_NOT_FOUND`
- **Fix**: `mcopy -i dist/test_esp.img -o dist/kernel.elf ::kernel.elf`

### Fix 3: GetMemoryMap Buffer Too Small (seconda chiamata)
- **Sintomo**: `GetMemMap final: EFI_BUFFER_TOO_SMALL (0x8000000000000005)`
- **Causa**: `final_map_size = map_size` usava la dimensione aggiornata da UEFI dopo la prima chiamata (byte effettivi usati), non il buffer allocato; nuovi descrittori aggiunti da allocazioni intermedie non entravano
- **Fix**: aggiunta variabile `alloc_buf_size = map_size` prima della prima `GetMemoryMap`, usata per la seconda chiamata

### Fix 4: ExitBootServices EFI_INVALID_PARAMETER — Retry Loop
- **Sintomo**: `ExitBootServices: EFI_INVALID_PARAMETER (0x8000000000000002)`
- **Causa**: chiamate `puts16` tra `GetMemoryMap` e `ExitBootServices` facevano allocare memoria al firmware, invalidando il MapKey
- **Fix**: retry loop silenzioso — `GetMemoryMap` + `ExitBootServices` senza nessuna chiamata a console in mezzo; aggiunto `#define EFI_INVALID_PARAMETER` mancante in `efi.h`

### Fix 5: GOP Use-After-Free dopo ExitBootServices
- **Sintomo**: `#PF` a RIP spurio dopo "[BOOT] Calling ExitBootServices", RAX = `0x894D5741FA1E0FF3`
- **Causa**: `gop->Mode->Info` acceduto dopo `ExitBootServices` (puntatori a memoria UEFI freed)
- **Fix**: salvataggio di `FrameBufferBase`, `HorizontalResolution`, `VerticalResolution`, `PixelsPerScanLine` in variabili locali PRIMA di `GetMemoryMap`/`ExitBootServices`

### Fix 6: GOP Struct Layout Errate in efi.h (3 bug)
- **Sintomo**: `gop` validato (`0x80000000`), ma struct letta con offset sbagliati → puntatori garbage
- **Bug 1**: `EFI_GRAPHICS_OUTPUT_PROTOCOL` — mancava campo `Blt` (8 byte) a offset 16 → `Mode` letto a +16 invece di +24
- **Bug 2**: `EFI_GRAPHICS_OUTPUT_PROTOCOL_MODE` — campi in ordine errato; `FrameBufferBase` a offset 0 invece di 24 (spec UEFI: `MaxMode`, `Mode`, `*Info`, `SizeOfInfo`, `FrameBufferBase`, `FrameBufferSize`)
- **Bug 3**: `EFI_GRAPHICS_OUTPUT_MODE_INFORMATION` — mancava `PixelInformation[4]` (12 byte) → `PixelsPerScanLine` a offset 16 invece di 32
- **Fix**: riscrittura completa di tutte e tre le struct in `efi.h` conformi alla spec UEFI §12.9

### Fix 7: _start 32-bit incompatibile con Long Mode UEFI → _uefi_start
- **Sintomo**: `_uefi_start` non ancora definito; boot UEFI chiamava `e_entry` = `_start` (codice BITS 32)
- **Causa**: `_start` è codice Multiboot2 32-bit; chiamato da long mode UEFI → istruzione `A3` letta come 9-byte in 64-bit (misalignment); poi `jmp 0x08:long_mode` (opcode `0xEA`) = invalid in 64-bit → `#UD` → triple fault silenzioso (no IDT)
- **Fix**: aggiunto entry point `_uefi_start` BITS 64 in `boot/boot.asm` — ricarica GDT, segmenti, stack (`lea rsp, [rel stack_top]`), chiama `kernel_main` via SysV ABI
- **Fix complementare**: `uefi/elf_load.c` — aggiunto lookup simbolo ELF `_uefi_start` nella symbol table; se trovato, sovrascrive `e_entry` come indirizzo di entrata
