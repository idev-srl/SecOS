# M36 — Exploit mitigations (Phase L pt 2)

CPU-rooted exploit mitigations, enabled on the BSP and every AP via
`cpu_enable_mitigations()` (CPUID-gated).

- **SMEP** (`CR4.SMEP`): the kernel can never execute a ring-3 page → defeats
  ret2usr. Verified ON with `-cpu Haswell` (boots fully, no faults). The default
  QEMU CPU lacks it (logs `n/a`); real HW (Braswell) has it.
- **Stack canaries**: `-fstack-protector-strong` across the whole kernel +
  `__stack_chk_guard`/`__stack_chk_fail` (halts loudly on a corrupted canary).
- **W^X on the 0–512 MB low identity map** (deferred since M12): the kernel runs
  from the high half, so nothing legitimately executes from the low identity map
  — it is now **NX** (a *separate* low PDT, no longer shared with the executable
  high-half PDT). The first 2 MB stays executable for the SMP AP trampoline
  (runs at phys `0x8000` on the kernel CR3 before jumping high). DMA is data
  access, unaffected by NX.
- **SMAP infrastructure**: CPUID detection + `stac`/`clac` bracketing in the
  `user_copy` primitives (`g_smap_enabled`), gated behind `-DSECOS_SMAP`.
  Enabling it system-wide still needs a user-pointer audit — several syscalls
  (`SYS_OPEN` → `vfs_lookup`) pass a user path deep into the kernel — so it's
  opt-in for now.

Logs `[M36] mitigations: SMEP=.. SMAP=.. stack-canary=on`. Both smoke paths PASS,
0 warnings/exceptions.
