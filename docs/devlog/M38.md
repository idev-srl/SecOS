# M38 — WiFi: Atheros AR9565 (ath9k) scaffold + WPA2 crypto

Targets the WiFi in the **ASUS E406S**: Qualcomm Atheros **AR9565** (PCI
`168c:0036`). Confirmed on the machine via SecOS `lspci` (`2:0.0 168C:0036
cls=02/80/00`) and Linux (`ath9k`, no firmware module). ath9k-class chips need
**no firmware blob** (the MAC/baseband run from on-chip ROM) — the one property
that makes a from-scratch driver tractable, unlike Intel/Realtek.

## Honest scope

**Done + provable:**
- `drivers/ath9k.{c,h}`: PCI attach for the AR9300 family (probe
  `168c:0030..0037`), BAR0 mapped via the physmap, MMIO + bus-master enabled,
  guarded RTC wake, reads `AR_SREV` (silicon revision → chip name) and
  `AR_STA_ID0/1` (MAC). On the ASUS this would identify the AR9565 and respond.
  Integrated into `net_init`; `wifi` shell command reports it.
- `net/ieee80211.h`: 802.11 frame structures (mgmt/beacon/IEs, RSN, scan result).
- **WPA2 crypto, KAT-validated at boot** (`crypto/sha1.c`, `crypto/wpa2.c`):
  SHA-1, HMAC-SHA1, **PBKDF2-HMAC-SHA1** (the WPA2-PSK PMK), AES-128, AES-CTR.
  Verified against:
  - IEEE 802.11i PBKDF2 vector: `("password","IEEE",4096)` →
    `f42c6fc5…9710a12e` — **PASS**,
  - FIPS-197 AES-128 vector — **PASS**.

  Both run in the boot crypto self-test (`[WPA2] … KAT PASS`).
