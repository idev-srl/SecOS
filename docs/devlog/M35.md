# M35 — Generalized capability model + audit + key revocation (Phase L pt 1)

Lifts M11's driver-capability idea to **all** processes as a least-privilege
model, rooted in the Ed25519 signature.

## Trust model

**Ambient by default** (a signed process keeps full access — signature = trust).
A manifest may **opt into confinement** by setting `MANIFEST_FLAG_CAP_ENFORCE`;
the kernel then restricts it to exactly the capabilities its signed flags
declare. A process cannot widen its own set (flags are covered by the signature).
Backward compatible: existing programs don't set `CAP_ENFORCE` and keep ambient
access.

## What shipped

- **Capability bits** in the signed manifest `flags` (no format change — uses
  free bits, so they're signature-rooted): `CAP_FS_READ/FS_WRITE/PROC/IPC/
  SIGNAL/TIME` (+ existing `CAP_NET`). `MANIFEST_CAP_MASK` is the granted subset.
- **`kernel/cap.{c,h}`**: `cap_allowed`/`cap_check` + a 64-entry **audit ring**
  (`[AUDIT]` debugcon mirror, queryable). `process_t` gains `cap_enforce`/
  `cap_mask`, set from the manifest.
- **Enforcement** (`syscall_dispatch` + `syscall_trap`): `CAP_GATE` on
  spawn/fork/wait (PROC), create/mkdir/unlink/chmod/chown/utimes/symlink/mount/
  umount/open-for-write (FS_WRITE), open/stat/getdents (FS_READ), msg_send/recv/
  pipe (IPC), kill (SIGNAL). Denials return `-1` and are audited. (`CAP_NET`
  keeps its M24 "required" semantics.)
- **Shell `audit`** dumps the log.
- **Keyring revocation** (`mm/elf_sign.c`): `elf_sign_revoke_key()` /
  `elf_sign_key_revoked()` — a signature from a revoked `key_id` is refused even
  if cryptographically valid (retire a compromised signer without re-keying).

## Demo (`M35_CAP_DEMO`)

`user/m35_caps.c` + `user/note_confined.S` (manifest `CAP_ENFORCE|CAP_FS_READ|
CAP_TIME`): `getticks` + read `/proc/version` **succeed**; `create`, `spawn`,
`pipe`, `socket` are all **DENIED** and audited. Verified: 4 audit events, no
`[EXC]`. Both smoke paths PASS.
