# M6 Devlog — Minimal Context Switch (Saved Trapframe + iretq)

**Branch:** `milestone/M1` (on top of M5)
**Tag:** —
**Status:** COMPLETE

---

## Summary

M6 adds the infrastructure for real context switching between processes using
the canonical `trapframe_t` layout introduced in M5. A process now carries a
persistent trapframe; switching restores all GPRs and `iretq`s into the target
address space.

Relevant commit:
- `1ba4fc3` [M6] Minimal context switch via saved trapframe + iretq

---

## Changes

- `kernel/process.h` — adds `trapframe_t* tf` to `process_t`.
- `kernel/process.c` — `process_create_from_elf` allocates a trapframe and
  builds the initial iret frame: `RIP = entry`, `RSP = stack_top`,
  `RFLAGS = 0x202`, `CS = 0x08`, `SS = 0x10` (kernel selectors for now —
  ring-3 selectors `0x23`/`0x1B` are wired up in M7). `process_destroy` frees
  the trapframe.
- `arch/x86/context_switch.c` — `arch_switch_to_process()` loads the target
  address space (`vmm_switch_space`) then calls `arch_iret_to_tf`. Panics if
  `tf` is NULL or the CR3 switch fails.
- `arch/x86/context_switch_asm.asm` — `arch_iret_to_tf` builds the CPU iret
  frame on the stack from the trapframe struct, restores all 15 GPRs, then
  `iretq`.
- `kernel/sched.c` — `sched_yield` calls `arch_switch_to_process(next)` when
  `next->tf` is available (does not return; the resumed process returns via
  trap/iret).
- `kernel/syscall_trap.c` — `syscall_handler` copies the on-stack trapframe
  into the persistent `current->tf` heap copy, with the return value patched
  into `rax`.
- `kernel/panic.c` — `exception_handler` copies the trapframe into
  `current->tf` for debugging/resume.
