# M12 — Memory scalability + W^X hard gate

**State:** core done. Self-test harness **51/51** (was 47/47; +4 M12 assertions).
Scope note: M12 as a whole also lists a higher-half kernel relocation and full
demand paging — **deferred**, with rationale below. The two testable done-criteria
("PMM reports >512 MB free on a 2 GB VM" and "a W+X page request is rejected")
are met.

## Goal

Let the kernel manage **all** RAM (not a 512 MB slice), serve allocations larger
than one page reliably (the bug M11 hit), and make W^X a hard runtime invariant
rather than a convention.

## What landed

### PMM scalability (`mm/pmm.c`)
- **Removed the clamps**: the 512 MB `total_frames` cap in
  `pmm_build_from_regions`, and the 128 MB per-region identity clamps in
  `pmm_init` (MB1) and `pmm_init_uefi`. The kernel now manages all reported RAM.
  Frames above the 512 MB identity window are reachable because the **physmap**
  at `VMM_PHYSMAP_BASE` already maps all physical memory, and consumers address
  frames via `phys_to_virt`. A defensive cap keeps the frame bitmap ≤ 32 MB
  (≈1 TB RAM) so a pathological/sparse memory map can't blow the bitmap, which
  lives at `_kernel_end` inside the identity window.
- **Faster allocation**: `find_free_frame` skips fully-used 32-bit bitmap words
  and starts from a rolling `next_free_hint` (no more O(n) rescan from frame 0
  on every alloc); `pmm_free_*` rewind the hint so freed space is reused soon.
- **Contiguous allocation**: `pmm_alloc_contiguous(n)` / `pmm_free_contiguous`
  find/free a run of `n` consecutive free frames — the backing the heap needs
  for multi-frame blocks.
- Debugcon report `[PMM] total_MB=.. free_MB=.. frames=..` so memory scaling is
  verifiable non-interactively. On `-m 2G`: **free ≈ 2045 MB** (was ≤512).

### Heap: physmap-addressed + multi-frame (`mm/heap.c`)
- The heap now addresses its memory through the **physmap** (`phys_to_virt`)
  instead of the identity map, so it works with any frame the PMM hands out —
  including frames above 512 MB.
- `expand_heap` allocates **as many physically-contiguous frames** as the request
  needs (via `pmm_alloc_contiguous`); since the physmap maps contiguous physical
  memory to contiguous virtual memory, the region is one usable block.
- `kmalloc` now returns **NULL on failure** instead of silently handing back an
  undersized block. This is the root cause of the M11 gotcha: the old heap grew
  one frame at a time and any `kmalloc` > ~4 KB could overflow its block.
- Verified safe: no driver/DMA path uses `kmalloc` (virtio uses static,
  identity-mapped buffers), and nothing does `virt_to_phys` on a heap pointer.

### W^X hard gate (`mm/vmm.c`)
- `vmm_map` / `vmm_map_in_space` now **reject** any mapping that is writable and
  executable (`RW` set with NX clear) with `-5` and a `[VMM][WX]` log — before
  any page-table walk. Previously W^X was enforced only by convention plus the
  ELF loader rejecting W|X segments; now it is a hard invariant on the mapping
  path. Audited all callers: user code is mapped RX (no RW), user data and kernel
  pages RW+NX, so none regress. (The 0–512 MB identity huge-page map is built
  directly, not via `vmm_map`, and remains RWX — flagged for a future full W^X of
  the identity region.)
- `vmm_wx_selftest()` attempts a W+X mapping at boot and asserts it is refused
  (`[WX] W+X mapping rejected (good)`).

### Tests + closing the M11 loop
- Boot-time self-tests (every boot): `[WX]` (W+X refused) and `[HEAP] large
  kmalloc(64K) OK` (16 contiguous frames written and read back).
- The **M11 driver demo loads from the VFS again** (`/bin/driver`,
  `/bin/userprobe`, ~8 KB each): the exact ramfs-copy path that silently
  corrupted under the one-frame heap now works, proving the fix end-to-end.
- `tools/selftest.sh`: +4 M12 assertions, including a `-m 2G` boot asserting
  PMM free > 512 MB.

## Deferred (with rationale)

- **Higher-half kernel relocation** (`0xFFFFFFFF80000000`, drop the low identity
  map): the highest-risk, lowest-incremental-value piece. The physmap already
  gives the kernel high-half access to *all* RAM (the practical benefit). A true
  relocation must change both boot paths (MB2 32-bit entry + the UEFI loader's
  ELF mapping), the linker script, `-mcmodel`, and every identity-dependent spot
  (notably virtio DMA, which currently relies on `phys == virt` for its static
  buffers). Doing it safely needs dedicated work on both boot paths and is not
  worth destabilising a green tree for an aesthetic/hardening gain. Tracked for a
  later milestone.
- **Full demand paging**: `vmm_handle_page_fault` already has a demand-zero path
  keyed on `vmm_region_t`, but no regions are registered, so it is dormant.
  Wiring lazy user growth + per-process limits (beyond the existing manifest
  `max_mem` check) is left as follow-up.
- **Full identity-region W^X**: the 0–512 MB identity huge-page map is RWX;
  making it W^X-clean (split into per-section permissions) is follow-up.

## Files

- `mm/pmm.{h,c}` — clamps removed, word-skip + cursor allocator,
  `pmm_alloc_contiguous`/`pmm_free_contiguous`, debugcon report.
- `mm/heap.c` — physmap addressing, multi-frame `expand_heap`, NULL-on-fail.
- `mm/vmm.{h,c}` — W^X gate in `vmm_map`/`vmm_map_in_space`, `vmm_wx_selftest`.
- `kernel/kernel.c` — boot W^X + large-kmalloc self-tests; M11 demo back to VFS.
- `tools/selftest.sh` — +4 M12 assertions (2 G boot, W^X, large heap).
