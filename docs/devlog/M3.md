# M3 Devlog — User/Kernel Isolation & Process Hardening

**Branch:** `milestone/M1` (M3 commits applied on top of M2_STABLE)
**Tag:** `M3_ISOLATION_BASE`
**Status:** COMPLETE (4 commits, smoke-tested)

---

## Summary

M3 introduces the kernel/user isolation boundary as a verifiable security guarantee.
No new features were added; the work is purely defensive hardening of existing code paths.

Three areas were hardened:
1. **VMM supervisor enforcement**: `vmm_map()` rejects kernel VAs with `USER` bit;
   `vmm_harden_user_space()` fixed and `vmm_space_create_user()` hardened.
2. **copy_from_user / copy_to_user**: safe boundary-crossing primitives.
3. **Syscall hardening**: all user pointers validated or copied before kernel use.

## FASE 2 — Hardening

### 2.1 Supervisor Enforcement (`mm/vmm.c`)

**`vmm_map()` policy check:**
```c
if ((flags & VMM_FLAG_USER) && (virt >= 0xFFFF800000000000ULL)) {
    terminal_writestring("[VMM][M3] POLICY VIOLATION: kernel VA mapped with USER bit\n");
    return -4;
}
```
Eliminates V7. Return value `-4` = new error code for policy violation.

**`vmm_harden_user_space()` fixed:**
- Old: computed `virt_base = (i << 39)` without sign extension → always 0 for i=256..511 → condition always false → function was no-op (V6).
- New: iterates `i = 256..511` directly (x86-64 kernel-canonical half). Uses `phys_to_virt()` when physmap is initialized.

**`vmm_space_create_user()` defensive assert:**
After copying kernel PML4 entries (all with U stripped), a verification loop checks that PML4[256..511] have U=0. Any stray U=1 is stripped and logged.

### 2.2 copy_from_user / copy_to_user (`mm/user_copy.h`, `mm/user_copy.c`)

```c
#define USER_ADDR_MAX  0x0000800000000000ULL  /* x86-64 user canonical limit */
#define EFAULT 14

int user_range_valid(const void* ptr, size_t len);
int copy_from_user(void* dst,       const void* user_src, size_t len);
int copy_to_user  (void* user_dst,  const void* src,      size_t len);
```

`user_range_valid` checks: null, zero-length, start >= USER_ADDR_MAX, arithmetic overflow, end > USER_ADDR_MAX.
Copy functions return `-EFAULT` if range invalid; perform byte-by-byte copy otherwise.
No heap allocation. No dynamic memory.

### 2.3 Syscall Hardening (`kernel/syscall.c`)

Top-of-file comment: *"Direct user pointer dereference is forbidden."*

| Syscall | Before | After |
|---------|--------|-------|
| SYS_OPEN | direct `(char*)a0` to VFS | `user_range_valid(path, 1)` before call |
| SYS_READ | direct `(void*)a1` to VFS | `user_range_valid(buf, len)` before call |
| SYS_WRITE | direct `(void*)a1` to VFS | `user_range_valid(buf, len)` before call |
| SYS_DRIVER | direct `(driver_call_t*)a0` | `copy_from_user(&kdc, a0, sizeof)` → kernel copy |

SYS_DRIVER write-back: for `READ_REG` and `GET_INFO`, `copy_to_user()` writes `kdc.value` back to the user struct's `value` field. Eliminates V4, V5.

All invalid-pointer cases return `(uint64_t)(int64_t)-EFAULT`.
