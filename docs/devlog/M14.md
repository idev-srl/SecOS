# M14 — Full demand paging

**State:** done. Self-test harness **61/61** (was 56/56; +5 M14 assertions).
Demo gated behind `M14_DEMAND_DEMO`, off by default; normal boot reaches the shell.

## Goal

Stop eagerly mapping a process's address space at load. Instead, reserve the
virtual ranges and let pages materialize one at a time, on first touch, via the
page-fault handler. This was the headline deferred item from M12 (*"full demand
paging — the `vmm_region` path is dormant"*).

Before M14, `process_create_from_elf` mapped **every** page of every PT_LOAD
segment (copying file content + zeroing BSS) and all 8 stack pages up front. A
program reserving a large BSS or stack paid for all of it immediately, even if it
touched none of it.

## What landed

### Per-process VMAs — `mm/vma.{h,c}` (new)
A `vma_t` describes a contiguous, page-aligned virtual range that is **not**
eagerly mapped. Two kinds:
- `VMA_TYPE_ANON` — zero-fill on fault (user stack, BSS tail, future heap).
- `VMA_TYPE_FILE` — backed by a pinned ELF image; the faulting page is filled
  from the image and zero-padded outside the file window (leading page padding +
  BSS tail).

A `vma_set_t` (fixed `VMA_MAX=16` array) lives in each `process_t`. `vma_fault_in`
allocates a frame, fills it **through the physmap** (a kernel RW alias — so a code
page can be content-filled even though its USER mapping will be read-only RX),
then maps it with the VMA's leaf flags via `vmm_map_in_space`.

The FILE window is expressed as `(file_off, file_pad, file_len)`: content occupies
region offsets `[file_pad, file_pad+file_len)` and is sourced from
`image[file_off + (off - file_pad)]`. `vma_fault_in` intersects that window with
the faulting page and copies only the overlap — robust against any segment
page-offset, and it never leaks ELF-header bytes into the leading stack/data pad
(that pad is zeroed, not pulled from the file).

### Demand-paging ELF loader — `mm/elf.c` `elf_load_image_lazy`
Same security validation as the eager loader (reject W|X, validate file/virtual
range, require `p_align` 0 or 0x1000 — all enforced **at load**, fail-fast), but
instead of allocating/mapping/copying it registers one FILE VMA per PT_LOAD
segment and returns the **reserved footprint** (sum of segment page ranges). No
frame is touched and no page table is walked here. Code segments get RX leaf
flags, data segments RW+NX; `vmm_map_in_space` adds PRESENT and enforces the W^X
gate at fault time.

### Pinned image + lazy process creation — `kernel/process.c`
- `process_create_from_elf` now pins a **private copy** of the (already
  signature-verified) ELF image (`p->image`/`p->image_size`, `kfree`d in
  `process_destroy`); FILE VMAs reference it for the process lifetime. The M12
  heap handles the multi-KB allocation.
- The user stack is reserved as an ANON VMA (8 pages below `USER_STACK_TOP`); the
  **absence of a VMA below it is the guard** — a stack underflow finds no VMA and
  falls through to the unhandled-fault path. No eager stack pages, no explicit
  guard PTE.
- Nothing is eagerly mapped. `mapped_pages` tracking is gone; teardown of
  faulted frames is handled by `vmm_space_destroy`, which already frees every
  present leaf in the user range (so partially-faulted spaces free correctly).
- `user_mem_bytes`/`mapped_page_count` now report the **reserved footprint**.

### `max_mem` against the reserved footprint — `kernel/process.c`
The M13 manifest `max_mem` check now compares against the reserved footprint
(sum of VMA sizes), not lazily-mapped pages. Semantics are preserved and arguably
sharper: a program that **reserves** more address space than its signed limit is
refused at load regardless of how little it touches at runtime. (M13's max_mem
self-test still passes unchanged.)

### Page-fault handler — `mm/vmm.c` `vmm_handle_page_fault`
Rewritten around the per-process VMAs. On a **not-present** fault it looks up the
faulting address in `sched_get_current()->vmas` and, if found, materializes that
page and returns so the instruction retries. The dormant global `vmm_region[32]`
stub is removed. Success is quiet (a terse `[PF] demand page <addr>` on debugcon
— faults are now frequent); the verbose framebuffer diagnostic + halt is reserved
for genuine violations (protection fault, no VMA, or allocation failure).

**Key enabler:** `copy_from/to_user` dereferences user virtual addresses
**directly** (no separate PTE walk). So when a syscall touches a not-yet-faulted
user buffer, the **kernel itself** takes the #PF on that user address; the handler
keys on the address + VMA (not the U/S error-code bit), faults the page in, and
the kernel access resumes. Demand paging therefore covers syscall buffers for
free — no changes to `user_copy.c`.

### Demo + harness — `kernel/kernel.c` (`M14_DEMAND_DEMO`), `tools/selftest.sh`
The demo loads the signed `hello`, counts present user leaf pages **before** it
runs (`vmm_count_user_pages`, new) — `0` while the reserved footprint is `0x9000`
(9 pages) — then schedules it. Its code + stack pages fault in on demand
(`[PF] demand page 0x100000000` code, `0x3FFEFF000` stack), it prints and exits.
Net: **9 pages reserved, 2 actually materialized.** Five assertions added.

## Why it works / things that bit

- **Filling RX code pages:** the new frame is filled through its physmap alias
  (kernel RW), never through the user RX mapping — no W^X violation, no transient
  writable code page.
- **Teardown:** because `vmm_space_destroy` frees all present leaves, dropping the
  `mapped_pages` array introduced **no** leak and no double-free (faulted frames
  are present in the page tables at exit; never-touched reserved pages were never
  allocated). Verified: M8/M10 reap paths still show no PMM leak.
- **Guard page:** replacing the explicit not-present guard PTE with "no VMA below
  the stack" is strictly stronger — there's no PTE to accidentally flip present.

## Verification

- `tools/selftest.sh` → **61/61** (M4 + crypto KATs + M7 + M8 + M9 + M10×3 + M11
  + M12 + M13 + M14). Every ring-3 program in the suite now runs demand-paged.
- `smoke.sh --mb2` and `--uefi` both PASS; demand-page markers appear on both
  boot paths (`[PF] demand page 0x100000000` / `0x3FFEFF000`).

## Deferred / not done

- **Copy-on-write** (fork-style sharing) — we have no `fork`; not needed yet.
- **Page-out / swap** — no backing store beyond the pinned image; frames are
  freed only at process exit.
- **Per-fault process kill** — an unhandled user fault still halts the kernel
  (a clean SIGSEGV-style process teardown would need the trapframe threaded into
  the handler). Acceptable: with demand paging, an out-of-VMA fault is a genuine
  bug and the halt is a loud failure signal for the smoke tests.
- **Shared read-only text** across processes (a page cache) — each process pins
  its own image copy for now.
