# M13 — Usability & policy enforcement

**State:** core done. Self-test harness **56/56** (was 51/51; +5 M13 assertions).
Demo gated behind `M13_DEMO`, off by default; normal boot reaches the shell.

## Goal

Make the system more usable and the signed-manifest policy enforceable end to
end: run on-disk programs from the shell, enforce the manifest memory limit, add
a few useful syscalls, and provide minimal inter-process communication.

Roadmap done-criteria: *the shell runs on-disk programs* (already true since M10's
`run <path>`), and *a program exceeding its manifest `max_mem` is aborted at load*.

## What landed

### Manifest `max_mem` enforcement (headline) — `kernel/process.c`
- The loader already parsed `max_mem`; M13 makes the abort path **correct and
  leak-free**. When a process's mapped footprint exceeds the signed manifest's
  `max_mem` (0 = unlimited), `process_create_from_elf` now tears down via
  `elf_unload_process` + `vmm_space_destroy` (frees user pages, page-table
  frames, the private PML4[0] PDPT and the PML4, and `kfree`s the space) and
  frees `mapped_pages` — instead of the old partial cleanup that leaked the
  page tables / private PDPT. Emits `[M13] max_mem exceeded -> process REFUSED`.
- The signature covers the `.note.secos` manifest, so the limit is **trust-rooted**:
  a program cannot raise its own ceiling without invalidating its signature.

### New syscalls — `kernel/syscall.{h,c}`, `user/libsecos.*`
- `SYS_GETTICKS` (10): uptime in timer ticks. libc `getticks()`.
- `SYS_MSG_SEND` (11) / `SYS_MSG_RECV` (12): send/recv bytes on a kernel IPC
  channel. User pointers are validated (`user_range_valid`) and bounce-buffered
  (`copy_from_user`/`copy_to_user`), capped at 256 bytes per call — never
  dereferenced directly (the M3 contract). libc `msg_send()`/`msg_recv()`.

### Minimal IPC channels — `kernel/ipc.{c,h}`
- A small fixed set of kernel-owned byte ring buffers (`IPC_NUM_CHANNELS=4`,
  `IPC_CHAN_BYTES=512`) addressed by a small integer id. `ipc_send`/`ipc_recv`
  are non-blocking (recv returns 0 when empty). Initialised at boot (`ipc_init`).
- The channel is **kernel-owned and process-independent**, so two separately
  spawned ring-3 programs communicate without `fork`/fd inheritance (our process
  model loads a fresh signed ELF per spawn). A consumer polls with `sched_yield`.

### On-disk launch
- The shell `run <path>` (M10) remains the first-class way to launch a signed
  on-disk program; it is exercised by the M10 harness (signed ELF written to
  disk → read → verify → ring-3 → exit) across FAT32/ext2/ext4.

## Demo (`M13_DEMO`, debugcon, abridged)

```
[M13] --- manifest max_mem enforcement ---
[M13] max_mem exceeded -> process REFUSED (used=0x8000 limit=0x1000)
[M13] max_mem program REFUSED at load (good)
[M13] --- IPC channel 0 (producer/consumer) ---
[ipc_send] sent=10 ticks=113                 <- SYS_GETTICKS uptime, SYS_MSG_SEND
[M13] spawned ipc_recv
[ipc_recv] got: M13-IPC-OK                    <- received over kernel channel 0
[M13] DONE
```

The producer (`user/ipc_send`) sends `"M13-IPC-OK"` on channel 0 and reports its
uptime, then exits; the consumer (`user/ipc_recv`), spawned afterwards, reads the
message the kernel kept queued. A signed program whose manifest declares
`max_mem=4 KB` (`user/maxmem`, built from `user/note_maxmem.S`) is refused at
load because its real footprint (≈32 KB incl. the guard-paged stack) exceeds it.

## Files

- `kernel/process.c` — leak-free `max_mem` abort + `[M13]` marker.
- `kernel/syscall.{h,c}` — `SYS_GETTICKS` / `SYS_MSG_SEND` / `SYS_MSG_RECV`.
- `kernel/ipc.{c,h}` — kernel IPC channels (ring buffers). `kernel/kernel.c` —
  `ipc_init()` at boot + `M13_DEMO` gate.
- `user/libsecos.*` — `getticks` / `msg_send` / `msg_recv`.
- `user/ipc_send.c`, `user/ipc_recv.c`, `user/note_maxmem.S`; `Makefile`
  user-progs builds+signs `crypto/user_{ipc_send,ipc_recv,maxmem}_elf.h`.
- `tools/selftest.sh` — +5 M13 assertions.

## Deferred (future)

- Blocking `SYS_SLEEP` / channel wait (current IPC recv is poll + yield);
  `argv`/environment passing to spawned programs; richer pipe semantics
  (multiple readers, EOF). The current channels are a minimal, demonstrable IPC.
